## Q01. C언어 — 배열 인덱스 vs 포인터 연산 + 평균 계산

```c
#include <stdio.h>

double arr1(int p[], int len) {
    double av = 0;
    int i;
    for (i = 0; i < len; i++) {
        av += (double) p[i];
    }
    return av / len;
}

double arr2(int * p, int len) {
    double av = 0;
    int i;
    for (i = 0; i < len; i++) {
        av += (double)( * (p + i));
    }
    return av / len;
}

int main() {
    int arr[10] = {80, 20, 50, 55, 45, 95, 55, 10, 40, 80};
    int len = 10;

    printf("%.2f", arr1(arr, len) + arr2(arr, len));

    return 0;
}
```

**정답**: `106.00`

---

### 풀이

**① arr1 vs arr2 — 동일한 함수**

두 함수는 표현 방식만 다를 뿐 **완전히 동일한 동작**을 합니다.

```c
p[i]       // 배열 인덱스 방식
*(p + i)   // 포인터 연산 방식 — 완전히 동일
```

C에서 `p[i]`는 컴파일러가 내부적으로 `*(p + i)`로 변환함

**② 배열 합계 계산**

| 인덱스 | 값 |
|--------|-----|
| arr[0] | 80 |
| arr[1] | 20 |
| arr[2] | 50 |
| arr[3] | 55 |
| arr[4] | 45 |
| arr[5] | 95 |
| arr[6] | 55 |
| arr[7] | 10 |
| arr[8] | 40 |
| arr[9] | 80 |
| **합계** | **530** |

**③ 평균 계산**

```
arr1(arr, 10) = 530.0 / 10 = 53.0
arr2(arr, 10) = 530.0 / 10 = 53.0
```

**④ 최종 출력**

```
arr1 + arr2 = 53.0 + 53.0 = 106.0
printf("%.2f", 106.0) → 106.00
```

---

### 번외 — `%.2f` 서식 지정자

| 서식 | 의미 |
|------|------|
| `%f` | 실수 출력 (기본 소수점 6자리) |
| `%.2f` | 소수점 **2자리**까지 출력 |
| `%.0f` | 소수점 없이 정수처럼 출력 |

```c
printf("%f",   106.0);  // 106.000000
printf("%.2f", 106.0);  // 106.00
printf("%.0f", 106.0);  // 106
```

---

### 번외 — 배열 인덱스 vs 포인터 연산

```c
int arr[] = {10, 20, 30};
int *p = arr;

arr[0] == *(p + 0) == *p     // 10
arr[1] == *(p + 1)           // 20
arr[2] == *(p + 2)           // 30
```

> C에서 배열 이름은 **첫 번째 원소의 주소**와 동일
> `arr1(int p[], int len)` 와 `arr2(int *p, int len)` 는 매개변수 선언도 동일한 의미

## Q04. 비기능적 요구사항 유형

> 1. 시스템 운영 중 로그 관리 및 모니터링 기능을 제공해야 한다.
> 2. 시스템 운영 시 최소 메모리 용량을 확보해야 하며, 자원 사용량은 제한 범위 내에 있어야 한다.
> 3. 사용자 요청에 대한 응답 시간은 최대 1분을 초과하지 않아야 한다.
>
> \[보기\] 신뢰성, 가용성, 운영, 유지보수성, 자원, 성능, 이식성, 보안, 품질

**정답**:
- ① **운영**
- ② **자원**
- ③ **성능**

---

### 풀이

| 번호 | 설명의 핵심 키워드 | 정답 |
|------|-----------------|------|
| ① | 로그 관리, 모니터링 | **운영** |
| ② | 메모리 용량, 자원 사용량 | **자원** |
| ③ | 응답 시간 | **성능** |

---

### 번외 — 비기능적 요구사항 전체 유형 정리

| 유형 | 설명 | 키워드 |
|------|------|--------|
| **성능** | 처리 속도, 응답 시간, 처리량 등 | 응답 시간, TPS, 처리량 |
| **자원** | 메모리, CPU, 저장 공간 등 자원 사용 제약 | 메모리, CPU 사용률 |
| **운영** | 로그 관리, 모니터링, 백업 등 운영 편의 | 로그, 모니터링, 백업 |
| **신뢰성** | 장애 없이 정상 동작하는 능력 | 오류율, MTBF |
| **가용성** | 시스템이 사용 가능한 시간 비율 | 가동률, 업타임 (예: 99.9%) |
| **유지보수성** | 수정·확장이 쉬운 정도 | 코드 가독성, 모듈화 |
| **이식성** | 다른 환경으로 옮겨도 동작하는 능력 | 플랫폼 독립성, 호환성 |
| **보안** | 인가되지 않은 접근 차단 | 인증, 암호화, 접근 제어 |
| **품질** | 전반적인 소프트웨어 품질 수준 | ISO 9126, 품질 기준 |

> **암기 포인트**:  
> - 응답 시간 → **성능**  
> - 메모리·CPU → **자원**  
> - 로그·모니터링 → **운영**  
> - 99.9% 가동 → **가용성**  
> - 장애 없는 동작 → **신뢰성**

## Q06. HDLC 프레임 구성 요소 및 동작 모드

> HDLC 구성 요소
>
> 1. HDLC 프레임의 구성 단위로, 실제 사용자 데이터를 전송하는 프레임
> 2. 데이터 링크의 흐름을 관리하고 오류 제어 및 통신 상태를 감시하는 프레임
> 3. 순서 번호 없이 링크 설정, 해제, 모드 설정 등 제어 기능을 수행하는 프레임
> 4. 두 국(Station)이 동등한 위치에서 서로 명령과 응답을 주고받는 모드
> 5. 종국(Secondary)이 주국(Primary)의 허가 없이도 자발적으로 응답을 전송할 수 있는 모드

**정답**:
- ① **정보 프레임 (I-Frame)**
- ② **감독 프레임 (S-Frame)**
- ③ **비번호 프레임 (U-Frame)**
- ④ **ABM (Asynchronous Balanced Mode, 비동기 균형 모드)**
- ⑤ **ARM (Asynchronous Response Mode, 비동기 응답 모드)**

---

### 풀이

**① HDLC 프레임 3종류**

| 프레임 | 영문 | 핵심 역할 | 순서 번호 |
|--------|------|---------|---------|
| **정보 프레임** | I-Frame (Information) | 실제 사용자 **데이터 전송** | 있음 |
| **감독 프레임** | S-Frame (Supervisory) | **흐름 제어·오류 제어**·상태 감시 | 있음 |
| **비번호 프레임** | U-Frame (Unnumbered) | 링크 **설정·해제·모드 설정** | **없음** |

> 구분 포인트: "순서 번호 없이"라는 말이 나오면 → **U-Frame**

---

**② HDLC 동작 모드 3종류**

| 모드 | 약자 | 구성 | 특징 |
|------|------|------|------|
| **정규 응답 모드** | NRM | 비균형 (주국↔종국) | 종국은 **주국의 허가**를 받아야만 송신 가능 |
| **비동기 균형 모드** | ABM | **균형** (복합국↔복합국) | 두 국이 **동등한 위치**에서 명령·응답 주고받음 |
| **비동기 응답 모드** | ARM | 비균형 (주국↔종국) | 종국이 **허가 없이도 자발적**으로 응답 전송 가능 |

> 암기법: **N**RM(Normal, 허가 필요) → **A**RM(Async, 허가 없이) → **AB**M(Balanced, 동등)
>
> - 동등한 위치 → **ABM**
> - 허가 없이 자발적 → **ARM**
> - 허가 받아야 → **NRM**
