## Q01

다음 Java 코드에서 알맞은 출력 값을 작성하시오.

```java
class Connection {
    private static Connection _inst = null;
    private int count = 0;

    static public Connection get() {
        if (_inst == null) {
            _inst = new Connection();
            return _inst;
        }
        return _inst;
    }

    public void count() { count++; }
    public int getCount() { return count; }
}

public class main {
    public static void main(String[] args) {
        Connection conn1 = Connection.get();
        conn1.count();
        Connection conn2 = Connection.get();
        conn2.count();
        Connection conn3 = Connection.get();
        conn3.count();
        conn1.count();
        System.out.print(conn1.getCount());
    }
}
```

### 풀이

**핵심 개념 — 싱글톤 패턴(Singleton Pattern)**

`Connection.get()`은 싱글톤 패턴으로 구현되어 있습니다.

- `_inst`는 **static** 변수 → 클래스 전체에서 하나만 존재
- `_inst`가 `null`이면 새 객체를 생성하고 저장
- `_inst`가 이미 있으면 기존 객체를 그대로 반환

따라서 `conn1`, `conn2`, `conn3`은 **모두 동일한 객체**를 가리킵니다.

**실행 순서 추적**

| 단계 | 코드 | _inst 상태 | count |
|------|------|-----------|-------|
| 1 | `conn1 = Connection.get()` | null → 새 객체 생성 | 0 |
| 2 | `conn1.count()` | 동일 객체 | **1** |
| 3 | `conn2 = Connection.get()` | _inst 있음 → 기존 객체 반환 | 1 |
| 4 | `conn2.count()` | conn1과 같은 객체 | **2** |
| 5 | `conn3 = Connection.get()` | _inst 있음 → 기존 객체 반환 | 2 |
| 6 | `conn3.count()` | conn1과 같은 객체 | **3** |
| 7 | `conn1.count()` | 동일 객체 | **4** |
| 8 | `conn1.getCount()` | count 반환 | → **4** |

conn1 = conn2 = conn3 (모두 같은 객체이므로 count를 공유)

### 정답

```
4
```

## Q02

다음 C 코드에서 알맞은 출력 값을 작성하시오.

```c
#include <stdio.h>

int main() {
    int v1 = 0, v2 = 35, v3 = 29;

    if(v1 > v2 ? v2 : v1) {
        v2 = v2 << 2;
    } else {
        v3 = v3 << 2;
    }

    printf("%d", v2+v3);
}
```

### 풀이

**① 조건식 분석:** `v1 > v2 ? v2 : v1`

삼항 연산자 `조건 ? 참 : 거짓` 형태입니다.

- v1 = 0, v2 = 35
- `v1 > v2` → `0 > 35` → **false**
- false이므로 `: v1` 선택 → 결과값 = **v1 = 0**

**② if 조건 판단:** `if(0)`

C에서 0은 **false**이므로 → **else 블록 실행**

**③ else 블록:** `v3 = v3 << 2`

`<<`는 왼쪽 비트 시프트 연산자 (`<< n` = ×2ⁿ)

| 단계 | 계산 |
|------|------|
| v3 원래 값 | 29 |
| 29를 2진수로 | 0001 1101 |
| 왼쪽으로 2칸 시프트 | 0111 0100 |
| 10진수로 변환 | **116** (= 29 × 4) |

**④ 최종 출력:** `v2 + v3 = 35 + 116 = 151`

### 정답

```
151
```

## Q04

다음 C 코드에서 알맞은 출력 값을 작성하시오.

```c
#include <stdio.h>
#include <string.h>

void reverse(char* str) {
    int len = strlen(str);
    char temp;
    char* p1 = str;
    char* p2 = str + len - 1;
    while (p1 < p2) {
        temp = *p1;
        *p1 = *p2;
        *p2 = temp;
        p1++;
        p2--;
    }
}

int main(int argc, char* argv[]) {
    char str[100] = "ABCDEFGH";
    reverse(str);
    int len = strlen(str);
    for (int i = 1; i < len; i += 2) {
        printf("%c", str[i]);
    }
    printf("\n");
    return 0;
}
```

### 풀이

**① reverse 함수 — 문자열 뒤집기**

p1은 앞에서, p2는 뒤에서 시작해 서로를 향해 좁혀가며 swap

| 단계 | p1 | p2 | swap 후 문자열 |
|------|----|----|----------------|
| 1 | A | H | HBCDEFGA |
| 2 | B | G | HGCDEFBA |
| 3 | C | F | HGFDECBA |
| 4 | D | E | HGFEDCBA |
| 5 | E | D | p1 ≥ p2 → 종료 |

reverse 결과: **`"HGFEDCBA"`**

**② for 루프 — 홀수 인덱스만 출력**

i = 1부터 시작, 2씩 증가 (i = 1, 3, 5, 7)

| i | str[i] | 출력 |
|---|--------|------|
| 1 | G | G |
| 3 | E | E |
| 5 | C | C |
| 7 | A | A |

아래 네트워크에서 라우터를 통한 할당 가능한 2번, 4번, 5번의 IP를 작성하시오.

- 할당 가능 범위: 192.168.35.1 ~ 192.168.35.254

- `192.168.35.0` → 네트워크 주소 (호스트 할당 불가 ✕)

**2번 = 192.168.35.72**

---

- /22 → 서브넷 마스크 255.255.252.0
- 세 번째 옥텟 계산: `10 & 252 = 00001010 & 11111100 = 00001000 = 8`
- 네트워크 주소: **129.200.8.0**
- 할당 가능 범위: 129.200.8.1 ~ 129.200.11.254

보기 중 129.200.x.x:
- `129.200.8.0` → 네트워크 주소 (호스트 할당 불가 ✕)
- `129.200.8.249` → 129.200.8.0/22 범위 내 ✓

**4번 = 129.200.8.249**

---

**⑤ 5번 — 6번(192.168.36.24/24)과 같은 네트워크**

- /24 → 서브넷 마스크 255.255.255.0
- 네트워크 주소: **192.168.36.0**
- 할당 가능 범위: 192.168.36.1 ~ 192.168.36.254

보기 중 192.168.36.x:
- `192.168.36.0` → 네트워크 주소 (호스트 할당 불가 ✕)

**5번 = 192.168.36.249**

## Q17

다음 내용에서 보기에서 알맞는 용어를 골라 작성하시오.

- 불특정 다수가 아닌 명확한 표적을 정하여 지속적인 정보수집 후 공격을 감행한다.
- 시스템에 직접 침투하는 것뿐 아니라 표적 내부 직원들이 이용하는 다양한 단말을 대상으로 한다.
- 한 가지 기술만이 아닌 Zero-day 취약점, 악성코드 등 다양한 보안 위협 공격 기술을 사용한다.
- 일반적으로 공격은 침투, 검색, 수집 및 유출의 4단계로 실행된다.

〈보기〉 ㄱ.사회공학 기법 / ㄴ.Adware / ㄷ.MITM / ㄹ.XDR / ㅁ.Replace attack / ㅂ.key logger attack / ㅅ.APT

### 풀이

**핵심 키워드 분석**

| 키워드 | 가리키는 개념 |
|--------|-------------|
| "명확한 **표적**을 정하여" | 불특정 다수 X, 특정 조직/기업 타깃 |
| "**지속적인** 정보수집" | 장기간에 걸친 공격 (Persistent) |
| "**Zero-day** 취약점, 악성코드 등 다양한 기술" | 고도화된 공격 (Advanced) |
| "**침투 → 검색 → 수집 → 유출** 4단계" | APT의 공격 단계 |

→ 모두 **APT(Advanced Persistent Threat, 지능형 지속 위협)**의 특징

**보기 전체 키워드 정리**

| 보기 | 풀네임 | 핵심 키워드 |
|------|--------|-----------|
| ㄱ. 사회공학 기법 | Social Engineering | 인간 심리 악용, 신뢰 관계 이용, 비기술적 수단으로 정보 탈취 |
| ㄴ. Adware | Advertising + Malware | 광고를 강제로 표시하는 소프트웨어, 수익 목적 |
| ㄷ. MITM | Man In The Middle | 송수신자 사이에 끼어들어 통신 가로채기/변조 |
| ㄹ. XDR | Extended Detection & Response | 보안 위협 탐지·대응 플랫폼, 여러 보안 도구 통합 |
| ㅁ. Replace attack | - | 정상 파일/데이터를 악성 파일로 교체하는 공격 |
| ㅂ. key logger attack | Key Logger | 키보드 입력(ID, 패스워드, 카드번호) 몰래 기록·탈취 |
| **ㅅ. APT** | Advanced Persistent Threat | **특정 표적 + 장기간 지속 + 다양한 고급 기술 + 4단계(침투→검색→수집→유출)** |

> APT vs 사회공학 기법 구분: 사회공학은 "수단(사람을 속이는 방법)", APT는 "전략(특정 표적을 오랜 기간 집요하게 공격)" — 사회공학 기법이 APT의 수단으로 쓰일 수 있음

### 정답

```
ㅅ. APT (Advanced Persistent Threat)
```

## Q14

아래 설명에 해당하는 답을 보기에서 골라 작성하시오.

   - 모든 분기와 조건의 조합을 고려하나 모든 조합을 테스트하는 대신에 테스트가 필요한 중요한 조합을 찾아내는데에 중점을 둔다.
   - 특정 조건을 수행할 때 다른 조건과는 상관없이 전체 결과에 영향을 미치는 조건만을 테스트한다.
   - 각각의 파라미터는 적어도 한 번은 최종 결과에 영향을 주어야 한다.

〈보기〉 ㄱ.구문 커버리지 / ㄴ.결정 커버리지 / ㄷ.조건 커버리지 / ㄹ.변경 조건/결정 커버리지 / ㅁ.다중 조건 커버리지 / ㅂ.경로 커버리지 / ㅅ.조건/결정 커버리지

### 풀이

**커버리지 종류 비교**

| 커버리지 | 핵심 개념 |
|---------|---------|
| ㄱ. 구문(Statement) | 모든 코드 라인을 한 번 이상 실행 |
| ㄴ. 결정(Decision/Branch) | 모든 분기의 True/False 각 한 번씩 |
| ㄷ. 조건(Condition) | 각 개별 조건의 True/False 각 한 번씩 |
| **ㅅ. 조건/결정** | 결정 커버리지 + 조건 커버리지 동시 만족; 각 파라미터(조건)가 결과에 한 번 이상 영향 |
| **ㄹ. 변경 조건/결정(MC/DC)** | 각 조건이 **다른 조건과 독립적**으로 전체 결과에 영향; 2^n 대신 n+1개의 중요 조합만 선택 |
| **ㅁ. 다중 조건** | 모든 개별 조건의 **모든 가능한 조합**(2^n)을 테스트 |
| ㅂ. 경로(Path) | 프로그램의 모든 가능한 실행 경로 테스트 |

**세 가지 설명은 모두 하나의 커버리지를 설명한 것입니다.**

| 설명 | 해당하는 MC/DC 특징 |
|------|-------------------|
| 모든 조합을 고려하나 중요한 조합에 중점 | 다중 조건(2^n)보다 적은 n+1개의 테스트 케이스만 필요 |
| 다른 조건과 상관없이 전체 결과에 영향 | 각 조건이 **독립적**으로 전체 결정에 영향을 미쳐야 함 |
| 각 파라미터가 적어도 한 번 최종 결과에 영향 | 모든 조건이 결과에 기여해야 함 |

### 정답


## Q11

다음 C언어의 알맞는 출력값을 작성하시오.

```c
#include <stdio.h>

typedef struct {
    int accNum;
    double bal;
} BankAcc;

double sim_pow(double base, int year) {
    int i;
    double r = 1.0;
    for (i = 0; i < year; i++) {
        r = r * base;
    }
    return r;
}

void initAcc(BankAcc *acc, int x, double y) {
    acc->accNum = x;
    acc->bal = y;
}

void xxx(BankAcc *acc, double *en) {
    if (*en > 0 && *en < acc->bal) {
        acc->bal = acc->bal - *en;
    } else {
        acc->bal = acc->bal + *en;
    }
}

void yyy(BankAcc *acc) {
    acc->bal = acc->bal * sim_pow((1 + 0.1), 3);
}

int main() {
    BankAcc myAcc;
    initAcc(&myAcc, 9981, 2200.0);
    double amount = 100.0;
    xxx(&myAcc, &amount);
    yyy(&myAcc);
    printf("%d and %.2f", myAcc.accNum, myAcc.bal);
    return 0;
}
```

### 풀이

**① initAcc(&myAcc, 9981, 2200.0)**

```
myAcc.accNum = 9981
myAcc.bal    = 2200.0
```

**② xxx(&myAcc, &amount) — amount = 100.0**

```
*en = 100.0
조건: *en > 0 && *en < acc->bal
    → 100 > 0 && 100 < 2200 → true
→ acc->bal = 2200.0 - 100.0 = 2100.0
```

**③ sim_pow(1.1, 3) — 1.1의 3제곱**

```
r = 1.0
i=0 : r = 1.0 × 1.1 = 1.1
i=1 : r = 1.1 × 1.1 = 1.21
i=2 : r = 1.21 × 1.1 = 1.331
return 1.331
```

**④ yyy(&myAcc)**

```
acc->bal = 2100.0 × 1.331
         = 2795.1
```

| 계산 | 값 |
|------|-----|
| 2100 × 1 | 2100.0 |
| 2100 × 0.3 | 630.0 |
| 2100 × 0.03 | 63.0 |
| 2100 × 0.001 | 2.1 |
| **합계** | **2795.1** |

**⑤ printf("%d and %.2f", 9981, 2795.1)**

- `%d` → 정수 그대로
- `%.2f` → 소수점 2자리 → 2795.10

### 정답

```
9981 and 2795.10
```

(2) 조건이 정확하게 '=' 등호로 일치하는 결과를 반환한다.  
(3) (2) 조인에서 조인에 참여한 속성이 두 번 나오지 않도록 중복된 속성을 제거한 결과를 반환한다.

### 풀이

INNER JOIN의 세부 종류 관계:

```
INNER JOIN
├── THETA JOIN  (=, ≠, <, >, ≤, ≥ 모든 비교 연산자)
│       └── EQUI JOIN  (= 만 사용)
│               └── NATURAL JOIN  (EQUI JOIN + 중복 속성 제거)
└── NON-EQUI JOIN  (= 제외한 나머지 연산자)
```

|------|------|---------|

| (2) EQUI JOIN | '=' 만 사용 | 있음 |
| (3) NATURAL JOIN | EQUI JOIN + 중복 속성 제거 | **없음** |

### 정답

```
(1) THETA JOIN (세타 조인)
(2) EQUI JOIN (동등 조인)
(3) NATURAL JOIN (자연 조인)
```

## Q06

아래 표에서 나타나고 있는 정규형을 작성하시오.

| 고객아이디 | 강좌명 | 강사번호 |
|-----------|--------|---------|
| apple | 영어회화 | P001 |
| banana | 기초토익 | P002 |
| carrot | 영어회화 | P001 |
| carrot | 기초토익 | P004 |
| orange | 영어회화 | P003 |
| orange | 기초토익 | P004 |

### 풀이

**기본키:** (고객아이디, 강좌명) — 복합키  
**비키 속성:** 강사번호

---

**① 1NF 확인 — 원자값**

모든 속성이 원자값(더 이상 분해 불가) → **1NF 만족 ✓**

---

**② 2NF 확인 — 부분 함수 종속 제거**

부분 함수 종속 = 기본키의 일부만으로 비키 속성이 결정되는 경우

- 강좌명만으로 강사번호 결정? → 영어회화에 P001, P003 두 개 존재 → **불가 ✕**
- 고객아이디만으로 강사번호 결정? → carrot이 P001, P004 두 개 존재 → **불가 ✕**
- (고객아이디, 강좌명) 전체로만 강사번호 결정 → **완전 함수 종속**

부분 함수 종속 없음 → **2NF 만족 ✓**

---

**③ 3NF 확인 — 이행 함수 종속 제거**

이행 함수 종속 = 비키 속성이 다른 비키 속성을 결정하는 경우

- 비키 속성이 강사번호 하나뿐 → 이행 종속 성립 불가

이행 함수 종속 없음 → **3NF 만족 ✓**

---

**④ BCNF 확인 — 모든 결정자가 후보키여야 함**

강사번호 → 강좌명이 성립하는가?

| 강사번호 | 강좌명 |
|---------|--------|
| P001 | 영어회화 |
| P002 | 기초토익 |
| P003 | 영어회화 |
| P004 | 기초토익 |

각 강사는 하나의 강좌만 담당 → **강사번호 → 강좌명 성립**  
그런데 강사번호는 후보키가 아님 → **BCNF 위반 ✕**

---

**정규형 판정 요약**

| 정규형 | 조건 | 판정 |
|--------|------|------|
| 1NF | 원자값 | ✓ |
| 2NF | 부분 함수 종속 없음 | ✓ |
| **3NF** | **이행 함수 종속 없음** | **✓** |
| BCNF | 모든 결정자가 후보키 | ✕ |

### 정답

```
제3정규형 (3NF)
```

> ※ 2NF가 아닌 이유: 이 테이블은 이미 2NF 조건(부분 함수 종속 없음)을 만족합니다.
> 2NF라고 하려면 2NF는 만족하지만 3NF는 위반해야 하는데,
> 이 테이블은 3NF까지 만족하므로 정규형은 **3NF**입니다.
