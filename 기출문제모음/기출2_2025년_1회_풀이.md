## Q05. Java — 예외 처리 (try-catch-finally)

```java
public class Main {
 
  public static void main(String[] args) {
 
    int a=5,b=0;
 
    try{
      System.out.print(a/b);
    }catch(ArithmeticException e){
      System.out.print("출력1");
    }catch(ArrayIndexOutOfBoundsException e) {
      System.out.print("출력2");
    }catch(NumberFormatException e) {
      System.out.print("출력3");
    }catch(Exception e){
      System.out.print("출력4");
    }finally{
      System.out.print("출력5");
    }
  }
}
```

**정답**: `출력1출력5`

---

### 풀이

**① 변수 초기화**
```
a = 5, b = 0
```

**② try 블록 실행**
```
a / b = 5 / 0  →  정수를 0으로 나눔 → ArithmeticException 발생
```

**③ catch 블록 순서대로 매칭**

| catch 블록 | 예외 타입 | 매칭 여부 |
|-----------|---------|---------|
| 1번째 | `ArithmeticException` | **매칭** → "출력1" 출력 후 종료 |
| 2번째 | `ArrayIndexOutOfBoundsException` | 실행 안 됨 |
| 3번째 | `NumberFormatException` | 실행 안 됨 |
| 4번째 | `Exception` | 실행 안 됨 (1번째에서 이미 잡힘) |

**④ finally 블록**
- `finally`는 예외 발생 여부, catch 처리 여부와 **무관하게 항상 실행**
- "출력5" 출력

**⑤ 최종 출력**
```
출력1출력5
```

---

### 번외 — Java 주요 예외 종류

| 예외 클래스 | 발생 상황 |
|------------|---------|
| `ArithmeticException` | 정수를 0으로 나눌 때 (`5/0`) |
| `ArrayIndexOutOfBoundsException` | 배열 범위 초과 접근 (`arr[10]`인데 크기가 3) |
| `NullPointerException` | null 객체의 메서드/필드 접근 |
| `NumberFormatException` | 숫자 형식 변환 실패 (`Integer.parseInt("abc")`) |
| `ClassCastException` | 잘못된 형 변환 |
| `StackOverflowError` | 재귀 호출 무한 반복 |

> **finally 특성**: `return`, `break`가 있어도, 예외가 잡히든 안 잡히든 finally는 반드시 실행됨. 단, `System.exit()`는 JVM을 종료하므로 finally도 실행 안 됨.

---

### 번외 — catch 블록 순서 주의사항

catch 블록은 **위에서부터 순서대로** 매칭되므로, 부모 예외를 자식 예외보다 먼저 쓰면 컴파일 오류 발생.

```java
// 잘못된 순서 (컴파일 오류)
catch(Exception e) { ... }          // 모든 예외의 부모
catch(ArithmeticException e) { ... } // 위에서 이미 잡히므로 unreachable

// 올바른 순서
catch(ArithmeticException e) { ... } // 구체적인 예외 먼저
catch(Exception e) { ... }           // 포괄적인 예외 나중에
```

## Q12. 결합도 (Coupling)

> 다음은 결합도와 관련된 내용이다. 보기에 알맞는 답을 골라 작성하시오.
>
> (1) 다른 모듈 내부에 있는 변수나 기능을 다른 모듈에서 사용하는 경우의 결합도
>
> (2) 모듈 간의 인터페이스로 배열이나 오브젝트, 자료구조 등이 전달되는 경우의 결합도
>
> (3) 파라미터가 아닌 모듈 밖에 선언되어 있는 전역 변수를 참조하고 전역 변수를 갱신하는 식으로 상호작용하는 경우의 결합도
>
> \[보기\] ㄱ. 자료 결합도 ㄴ. 스탬프 결합도 ㄷ. 제어 결합도 ㄹ. 공통 결합도 ㅁ. 내용 결합도 ㅂ. 외부 결합도

**정답**:
- (1) **ㅁ. 내용 결합도**
- (2) **ㄴ. 스탬프 결합도**
- (3) **ㄹ. 공통 결합도**

---

### 풀이

**결합도 전체 6종류** — 강함(나쁨) → 약함(좋음) 순서

암기법: **내공외제스자** (내용-공통-외부-제어-스탬프-자료)

| 순위 | 결합도 | 영문 | 설명 | 예시 |
|------|--------|------|------|------|
| 1 (가장 강함) | **내용** 결합도 | Content | 다른 모듈의 **내부 변수·코드를 직접** 참조·수정 | 모듈 A가 모듈 B의 내부 변수를 직접 변경 |
| 2 | **공통** 결합도 | Common | **전역 변수**를 여러 모듈이 공유·갱신 | `global_var`를 여러 모듈이 읽고 씀 |
| 3 | **외부** 결합도 | External | 외부에서 정의된 **데이터 형식·통신 프로토콜·디바이스 인터페이스**를 공유 | 외부 파일 포맷, 외부 기기 인터페이스 공유 |
| 4 | **제어** 결합도 | Control | **제어 신호(플래그, 스위치)** 를 파라미터로 전달하여 상대 모듈의 흐름을 제어 | `func(data, isFlag)` 에서 flag로 분기 제어 |
| 5 | **스탬프** 결합도 | Stamp | **배열·구조체·객체** 등 자료구조를 파라미터로 전달 (필요한 데이터만 있는데 전체 구조 전달) | `func(Student s)` 에서 이름만 필요한데 객체 전달 |
| 6 (가장 약함) | **자료** 결합도 | Data | **단순 기본 자료형** (int, String 등) 파라미터만 전달 | `func(int a, int b)` |

> **결합도는 낮을수록 좋다** (모듈 간 독립성 높음 = 유지보수 용이)

## Q13. Java — 상속·다형성·생성자 호출 순서

```java
public class Main {
    public static void main(String[] args) {
        new Child();
        System.out.println(Parent.total);
    }
}

class Parent {
    static int total = 0;
    int v = 1;

    public Parent() {
        total += (++v);
        show();
    }

    public void show() {
        total += total;
    }
}

class Child extends Parent {
    int v = 10;

    public Child() {
        v += 2;
        total += v++;
        show();
    }

    @Override
    public void show() {
        total += total * 2;
    }
}
```

**정답**: `54`

---

### 풀이

`new Child()` 호출 시 Java 실행 순서:
1. **Parent 필드 초기화** (`Parent.v = 1`)
2. **Parent() 생성자 실행**
3. **Child 필드 초기화** (`Child.v = 10`)
4. **Child() 생성자 실행**

---

**① Parent 필드 초기화**

```
static total = 0
Parent.v = 1
```

---

**② Parent() 생성자 실행**

```java
total += (++v);   // Parent의 v 사용
```
- `++v` → Parent.v = 1+1 = **2** (전위 증가)
- `total = 0 + 2` = **2**

```java
show();   // ← 실제 객체가 Child이므로 Child의 show() 호출! (다형성)
```

**Child.show() 실행:**
```java
total += total * 2;
// total = 2 + (2 × 2) = 2 + 4 = 6
```

| 시점 | total | Parent.v | Child.v |
|------|-------|----------|---------|
| Parent() 실행 후 | **6** | 2 | (아직 미초기화) |

---

**③ Child 필드 초기화**

```
Child.v = 10   (Parent.v와 별개의 변수 — 필드 섀도잉)
```

---

**④ Child() 생성자 실행**

```java
v += 2;
```
- `v`는 Child의 v (Parent.v를 가림)
- Child.v = 10 + 2 = **12**

```java
total += v++;
```
- `v++` 후위 증가: 현재 값 12를 먼저 사용 후 증가
- `total = 6 + 12` = **18**
- Child.v = 13 (사용 후 증가)

```java
show();   // Child의 show()
```

**Child.show() 실행:**
```java
total += total * 2;
// total = 18 + (18 × 2) = 18 + 36 = 54
```

| 시점 | total | Parent.v | Child.v |
|------|-------|----------|---------|
| Child() 실행 후 | **54** | 2 | 13 |

---

**⑤ 최종 출력**

```
System.out.println(Parent.total) → 54
```

---

### 번외 — 핵심 포인트 3가지

**1. 생성자 호출 순서**
> 항상 **부모 생성자 먼저** 실행 → 자식 생성자 실행
> (Child() 안에 `super()`가 없어도 자동 삽입)

**2. 다형성 — 생성자 안에서도 오버라이딩 적용**
> Parent() 안에서 `show()` 호출 시, 실제 객체 타입이 Child이므로 **Child의 show()가 호출됨**
> → 이 시점에 Child.v는 아직 초기화 전(0)이지만, show()는 total만 사용하므로 영향 없음

**3. 필드 섀도잉 (Field Shadowing)**
> Child의 `int v = 10`은 Parent의 `int v = 1`을 **가림(shadow)**
> 두 v는 완전히 별개의 변수:
> - Parent 메서드에서 `v` → Parent.v
> - Child 메서드에서 `v` → Child.v

## Q17. Python — 이진 트리 + 재귀 (홀수 레벨 합산)

```python
class Node:
    def __init__(self, value):
        self.value = value
        self.children = []

def tree(li):
    nodes = [Node(i) for i in li]
    for i in range(1, len(li)):
        nodes[(i - 1) // 2].children.append(nodes[i])
    return nodes[0]

def calc(node, level=0):
    if node is None:
        return 0
    return (node.value if level % 2 == 1 else 0) + sum(calc(n, level + 1) for n in node.children)

li = [3, 5, 8, 12, 15, 18, 21]
root = tree(li)
print(calc(root))
```

**정답**: `13`

---

### 풀이

**① 트리 구성 — `nodes[(i-1)//2].children.append(nodes[i])`**

인덱스 i의 부모 인덱스 = `(i-1) // 2` (배열로 표현한 이진 트리 공식)

| i | 부모 인덱스 `(i-1)//2` | 관계 |
|---|----------------------|------|
| 1 | 0 | nodes[0](3) → nodes[1](5) |
| 2 | 0 | nodes[0](3) → nodes[2](8) |
| 3 | 1 | nodes[1](5) → nodes[3](12) |
| 4 | 1 | nodes[1](5) → nodes[4](15) |
| 5 | 2 | nodes[2](8) → nodes[5](18) |
| 6 | 2 | nodes[2](8) → nodes[6](21) |

**트리 구조:**
```
           3       ← level 0 (짝수)
          / \
         5   8     ← level 1 (홀수)
        / \ / \
      12 15 18 21  ← level 2 (짝수)
```

---

**② calc 규칙**

```python
return (node.value if level % 2 == 1 else 0) + sum(...)
```

- `level % 2 == 1` (홀수) → node.value 더함
- `level % 2 == 0` (짝수) → 0 (더하지 않음)

| level | 짝/홀 | value 반영 여부 |
|-------|-------|--------------|
| 0 | 짝수 | **무시** |
| 1 | 홀수 | **더함** |
| 2 | 짝수 | **무시** |

---

**③ 재귀 추적**

```
calc(3, level=0)
  → 0  (level 0: 짝수, 3 무시)
  + calc(5, level=1)
      → 5  (level 1: 홀수, 5 더함)
      + calc(12, level=2) → 0  (짝수, 리프)
      + calc(15, level=2) → 0  (짝수, 리프)
      = 5 + 0 + 0 = 5
  + calc(8, level=1)
      → 8  (level 1: 홀수, 8 더함)
      + calc(18, level=2) → 0  (짝수, 리프)
      + calc(21, level=2) → 0  (짝수, 리프)
      = 8 + 0 + 0 = 8

최종: 0 + 5 + 8 = 13
```

### 번외 — 이진 트리 배열 인덱스 공식

배열로 이진 트리를 표현할 때:

| 관계 | 공식 |
|------|------|
| 인덱스 i의 **부모** | `(i - 1) // 2` |
| 인덱스 i의 **왼쪽 자식** | `2 * i + 1` |
| 인덱스 i의 **오른쪽 자식** | `2 * i + 2` |

```
인덱스:  0   1   2   3   4   5   6
값:     [3,  5,  8, 12, 15, 18, 21]

       index 0 (3)
       /         \
   index 1 (5)   index 2 (8)
   /      \      /       \
index3   index4  index5  index6
 (12)    (15)   (18)    (21)
```
