## Q01. Java 배열 참조 비교

```java
class Main {
    public static void main(String[] args) {
        int[] a = new int[]{1, 2, 3, 4};
        int[] b = new int[]{1, 2, 3, 4};
        int[] c = new int[]{1, 2, 3};

        check(a, b);
        check(a, c);
        check(b, c);
    }

    public static void check(int[] a, int[] b) {
        if (a==b) {
            System.out.print("O");
        } else {
            System.out.print("N");
        }
    }
}
```

### 핵심 개념

Java에서 `==`로 배열(객체)을 비교하면 **참조(메모리 주소)**를 비교한다.  
내용이 같아도 `new`로 따로 생성하면 서로 다른 객체이므로 `false`.

> 내용(값) 비교: `Arrays.equals(a, b)` 사용

### 실행 흐름

| 호출 | a | b | a==b | 출력 |
|------|---|---|------|------|
| check(a, b) | 객체A | 객체B | false | N |
| check(a, c) | 객체A | 객체C | false | N |
| check(b, c) | 객체B | 객체C | false | N |

### 정답

```
NNN
```

## Q06. Python 부분 문자열 카운트

```python
def fnCalculation(x, y):
    result = 0
    for i in range(len(x)):
        temp = x[i:i+len(y)]
        if temp == y:
            result += 1
    return result

a = "abdcabcabca"
p1 = "ab"
p2 = "ca"

out = f"ab{fnCalculation(a,p1)}ca{fnCalculation(a,p2)}"
print(out)
```

### 핵심 개념

`fnCalculation(x, y)` — x 문자열에서 y가 몇 번 등장하는지 카운트  
`x[i:i+len(y)]` — 슬라이딩 윈도우로 길이 len(y)의 부분 문자열 추출

### fnCalculation(a, "ab") 추적

`a = "abdcabcabca"` (인덱스 0~10)

| i | x[i:i+2] | == "ab"? |
|---|----------|---------|
| 0 | "ab" | ✓ result=1 |
| 1 | "bd" | ✗ |
| 2 | "dc" | ✗ |
| 3 | "ca" | ✗ |
| 4 | "ab" | ✓ result=2 |
| 5 | "bc" | ✗ |
| 6 | "ca" | ✗ |
| 7 | "ab" | ✓ result=3 |
| 8 | "bc" | ✗ |
| 9 | "ca" | ✗ |
| 10 | "a" | ✗ |

→ 반환값: **3**

### fnCalculation(a, "ca") 추적

| i | x[i:i+2] | == "ca"? |
|---|----------|---------|
| 3 | "ca" | ✓ result=1 |
| 6 | "ca" | ✓ result=2 |
| 9 | "ca" | ✓ result=3 |

→ 반환값: **3**

### f-string 결합

**f-string** — Python 3.6+에서 지원하는 문자열 포매팅 방식.  
문자열 앞에 `f`를 붙이고 `{}` 안에 변수나 식을 넣으면 값이 자동으로 삽입된다.

```python
name = "홍길동"
age = 25
print(f"이름: {name}, 나이: {age}")  # 이름: 홍길동, 나이: 25

# {} 안에 식도 가능
print(f"3 + 5 = {3 + 5}")  # 3 + 5 = 8
```

이 문제에서는:
```python
f"ab{fnCalculation(a,p1)}ca{fnCalculation(a,p2)}"
# → f"ab{3}ca{3}"
# → "ab3ca3"
```

### 정답

```
ab3ca3
```

## Q08. 패킷 교환 방식

### 개념 정리

패킷 교환 방식은 데이터를 패킷 단위로 쪼개어 전송하는 방식으로 두 종류가 있다.

| 구분 | 방식 | 특징 |
|------|------|------|
| 연결형 | 가상 회선(Virtual Circuit) | 전송 전 경로를 미리 설정, 모든 패킷이 같은 경로로 전달, 순서 보장 |
| 비연결형 | 데이터그램(Datagram) | 경로 미리 설정 안 함, 패킷마다 독립적으로 최적 경로 선택, 순서 보장 안 됨 |

### 정답

| 번호 | 정답 |
|------|------|
| ① 연결형 | 가상 회선(Virtual Circuit) |
| ② 비연결형 | 데이터그램(Datagram) |

### 번외 — 교환 방식 전체 분류

데이터 통신의 교환 방식은 크게 3가지로 나뉜다.

| 방식 | 설명 | 특징 |
|------|------|------|
| **회선 교환** (Circuit Switching) | 전송 전 물리적 전용 회선을 미리 확보 | 전화망(PSTN), 대역폭 낭비, 안정적 |
| **메시지 교환** (Message Switching) | 패킷 X, 메시지 전체를 저장 후 전달(Store & Forward) | 중간 노드에 메시지 전체 저장, 지연 큼 |
| **패킷 교환** (Packet Switching) | 데이터를 패킷 단위로 쪼개서 전송 | 인터넷의 기본 방식 |
| └ 가상 회선 | 경로 사전 설정, 같은 경로로 전달 | 순서 보장 |
| └ 데이터그램 | 패킷마다 독립 경로 | 순서 미보장, 유연함 |

> 정보처리기사에서 "패킷 교환 방식의 종류"를 물으면 **가상 회선 / 데이터그램** 두 가지가 정답  
> "교환 방식 전체"를 물으면 **회선 교환 / 메시지 교환 / 패킷 교환** 세 가지

## Q09. 모듈 응집도

### 지문 키워드 분석

- "실행 순서가 밀접한 관계" → 순서가 존재
- **"출력 자료가 다음 기능 원소의 입력 자료로 제공"** → 데이터가 다음으로 흘러감

→ **ㅂ. 순차적(Sequential)**

### 응집도 전체 종류 (강 → 약)

| 순위 | 종류 | 설명 |
|------|------|------|
| 1 | 기능적(Functional) | 모듈 내 모든 요소가 단일 기능만 수행 |
| 2 | **순차적(Sequential)** | 앞 기능의 출력이 다음 기능의 입력으로 연결 |
| 3 | 통신적(Communication) | 같은 입출력 자료를 사용하는 기능들의 묶음 |
| 4 | **절차적(Procedural)** | 순서대로 실행되지만 출력→입력 연결은 없음 |
| 5 | 시간적(Temporal) | 특정 시간에 함께 수행되는 기능들의 묶음 |
| 6 | 논리적(Logical) | 유사한 성격의 기능을 논리적으로 묶음 |
| 7 | 우연적(Coincidental) | 관련 없는 기능들의 우연한 집합 |

### 절차적 vs 순차적 차이

| 구분 | 절차적(Procedural) | 순차적(Sequential) |
|------|-------------------|-------------------|
| 공통점 | 순서가 존재함 | 순서가 존재함 |
| 차이점 | 단순히 순서대로 실행 | 앞 기능의 **출력**이 다음 기능의 **입력**으로 직접 연결 |
| 데이터 흐름 | 없음 | 있음 |
| 예시 | 파일 열기 → 읽기 → 닫기 (각 단계가 독립적) | 데이터 읽기 → 정렬 → 출력 (읽은 데이터가 정렬의 입력, 정렬 결과가 출력의 입력) |

> 핵심 구분: **출력이 다음 입력으로 이어지면 순차적, 그냥 순서만 있으면 절차적**

### 정답

```
ㅂ. 순차적(Sequential)
```

## Q11. RIP 최단 경로 계산

### 그래프

```
A --2-- B
A --1-- D
B --2-- D
D --2-- C
C --1-- E
E --2-- F
C --5-- F
```

### RIP vs OSPF 개념 비교

| 구분 | RIP | OSPF |
|------|-----|------|
| 알고리즘 | Distance Vector (Bellman-Ford) | Link State (Dijkstra) |
| 메트릭 | **홉 수(Hop Count)** — 링크 비용 무시 | **링크 비용(Cost)** — 실제 가중치 사용 |
| 최대 홉 | 15홉 (16=도달 불가) | 제한 없음 |

---

### RIP — A에서 각 노드까지 (홉 수 기준)

RIP는 링크 비용을 무시하고 **거쳐가는 링크 수(홉)**만 센다.

| 목적지 | 최단 경로 | 홉 수 |
|--------|-----------|-------|
| B | A → B | 1 |
| D | A → D | 1 |
| C | A → D → C | 2 |
| E | A → D → C → E | 3 |
| F | A → D → C → F | 3 |

> F까지: A→D→C→F = 3홉 vs A→D→C→E→F = 4홉 → RIP는 3홉 선택

---

### OSPF — A에서 각 노드까지 (Dijkstra, 비용 기준)

Dijkstra 실행 순서:

| 단계 | 방문 노드 | 갱신 |
|------|-----------|------|
| 초기 | A=0 | B=∞, C=∞, D=∞, E=∞, F=∞ |
| 1 | **A(0)** | B=2, D=1 |
| 2 | **D(1)** | B=min(2, 1+2)=2, C=1+2=3 |
| 3 | **B(2)** | 갱신 없음 |
| 4 | **C(3)** | E=3+1=4, F=3+5=8 |
| 5 | **E(4)** | F=min(8, 4+2)=6 |
| 6 | **F(6)** | 완료 |

| 목적지 | 최단 경로 | 비용 |
|--------|-----------|------|
| B | A → B | 2 |
| D | A → D | 1 |
| C | A → D → C | 3 |
| E | A → D → C → E | 4 |
| F | A → D → C → E → F | 6 |

> F까지: OSPF는 A→D→C→E→F(비용 6) 선택 — RIP의 A→D→C→F(비용 8)보다 실제로 더 효율적

## Q12. SRT 스케줄링 평균 대기시간

### 프로세스 정보

| 프로세스 | 도착 시간 | 서비스 시간 |
|----------|-----------|-------------|
| A | 0 | 8 |
| B | 1 | 4 |
| C | 2 | 9 |
| D | 3 | 5 |

### 핵심 개념

**SRT (Shortest Remaining Time)** = 선점형 SJF  
새 프로세스 도착 시, 현재 실행 중인 프로세스의 **남은 시간**과 비교 → 더 짧으면 선점

### 타임라인 추적

| 시간 | 이벤트 | 실행 | 각 프로세스 남은 시간 |
|------|--------|------|----------------------|
| t=0 | A 도착 | A | A=8 |
| t=1 | B 도착(4) vs A 남은(7) → **B 선점** | B | A=7, B=4 |
| t=2 | C 도착(9) vs B 남은(3) → B 계속 | B | A=7, B=3, C=9 |
| t=3 | D 도착(5) vs B 남은(2) → B 계속 | B | A=7, B=2, C=9, D=5 |
| t=5 | **B 완료** → 남은: A=7, C=9, D=5 → D 선점 | D | A=7, C=9, D=5 |
| t=10 | **D 완료** → 남은: A=7, C=9 → A 실행 | A | A=7, C=9 |
| t=17 | **A 완료** → 남은: C=9 → C 실행 | C | C=9 |
| t=26 | **C 완료** | — | — |

### 실행 순서 요약

```
t=0~1  : A 실행 (1초)
t=1~5  : B 실행 (4초) → B 완료
t=5~10 : D 실행 (5초) → D 완료
t=10~17: A 실행 (7초) → A 완료
t=17~26: C 실행 (9초) → C 완료
```

### 대기시간 계산

> 대기시간 = 완료시간 - 도착시간 - 서비스시간

| 프로세스 | 완료 시간 | 도착 시간 | 서비스 시간 | 대기 시간 |
|----------|-----------|-----------|-------------|-----------|
| A | 17 | 0 | 8 | 17-0-8 = **9** |
| B | 5 | 1 | 4 | 5-1-4 = **0** |
| C | 26 | 2 | 9 | 26-2-9 = **15** |
| D | 10 | 3 | 5 | 10-3-5 = **2** |

### 정답

평균 대기시간 = (9 + 0 + 15 + 2) / 4 = 26 / 4 = **6.5**

---

### 핵심 차이 요약

RIP는 F까지 **3홉** 경로(A→D→C→F, 실제 비용 8)를 선택하지만,  
OSPF는 **비용 6**인 경로(A→D→C→E→F, 4홉)를 선택한다.  
→ 홉 수가 적어도 비용이 클 수 있으므로 **OSPF가 더 정확한 경로 선택**을 한다.

## Q17. Java 재귀 — 중복 제거 후 역순 출력

```java
class Main {
    public static void main(String[] args) {
        String str = "abacabcd";
        boolean[] seen = new boolean[256];
        System.out.print(calculFn(str, str.length()-1, seen));
    }

    public static String calculFn(String str, int index, boolean[] seen) {
        if(index < 0) return "";
        char c = str.charAt(index);
        String result = calculFn(str, index-1, seen);
        if(!seen[c]) {
            seen[c] = true;
            return c + result;
        }
        return result;
    }
}
```

### 핵심 개념

- `seen[]`은 배열(참조형) → 모든 재귀 호출이 **공유**
- 재귀가 index=-1까지 내려간 후 index=0부터 올라오며 결과를 만듦
- `c + result` → 현재 문자를 **앞에 붙임** (prepend)
- 이미 seen이면 결과 그대로 반환 (중복 제거)

### 실행 추적

str = `"abacabcd"` (index 0~7)

| index | c | seen[c]? | result (받아온 값) | 반환값 |
|-------|---|----------|--------------------|--------|
| -1 | — | — | — | `""` |
| 0 | 'a' | false → true | `""` | `"a"` |
| 1 | 'b' | false → true | `"a"` | `"ba"` |
| 2 | 'a' | **true** | `"ba"` | `"ba"` |
| 3 | 'c' | false → true | `"ba"` | `"cba"` |
| 4 | 'a' | **true** | `"cba"` | `"cba"` |
| 5 | 'b' | **true** | `"cba"` | `"cba"` |
| 6 | 'c' | **true** | `"cba"` | `"cba"` |
| 7 | 'd' | false → true | `"cba"` | `"dcba"` |

첫 등장 순서: a(0), b(1), c(3), d(7) → `c + result`로 앞에 붙이므로 역순 = **dcba**

### 정답

```
dcba
```

## Q20. Java String split()

```java
class Main {
```
