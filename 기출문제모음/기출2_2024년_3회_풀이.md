## Q01. Java — String .equals() vs ==

```java
public class Main{
  static String[] s = new String[3];
 
  static void func(String[]s, int size){
    for(int i=1; i<size; i++){
      if(s[i-1].equals(s[i])){
        System.out.print("O");
      }else{
        System.out.print("N");
      }
    }
      for (String m : s){
        System.out.print(m);
      }
    }
 
  public static void main(String[] args){
    s[0] = "A";
    s[1] = "A";
    s[2] = new String("A");
 
    func(s, 3);
  }
}
```

**정답**: `OOAAA`

---

### 풀이

**① 배열 초기화**

| 인덱스 | 값 | 저장 방식 |
|--------|-----|-----------|
| s[0] | "A" | String Pool에서 같은 리터럴 참조 |
| s[1] | "A" | String Pool에서 같은 리터럴 참조 (s[0]과 동일 주소) |
| s[2] | new String("A") | `new`로 Heap에 새 객체 생성 → 주소는 다름, 값은 "A" |

**② func(s, 3) 실행 — 첫 번째 for 루프** (`i`는 1부터 size-1까지)

| i | 비교 | 메서드 | 결과 | 출력 |
|---|------|--------|------|------|
| 1 | s[0].equals(s[1]) | "A".equals("A") | true | **O** |
| 2 | s[1].equals(s[2]) | "A".equals("A") | true | **O** |

> **핵심**: `.equals()`는 **내용(값)** 을 비교한다. `==`는 주소(참조) 비교이지만, `.equals()`는 문자열의 실제 내용을 비교하므로 `new String("A")`도 "A"와 같다고 판단함.

**③ 두 번째 for-each 루프**

```
for (String m : s) → s[0]="A", s[1]="A", s[2]="A" 순서로 출력
```
출력: `AAA`

**④ 최종 출력**

```
O  O  A  A  A
```
→ `OOAAA`

---

### 번외 — `==` vs `.equals()` 비교

| 연산 | 비교 기준 | s[0] == s[1] | s[1] == s[2] |
|------|----------|-------------|-------------|
| `==` | 주소(참조) | true (같은 Pool 주소) | **false** (new로 다른 주소) |
| `.equals()` | 내용(값) | true | **true** |

만약 `==`을 사용했다면 → `ONAAa` 가 아닌 `ONAAA`가 출력되었을 것.

> String Pool: Java에서 문자열 리터럴은 String Pool에 저장되어 같은 값이면 동일한 객체를 재사용함. `new String()`은 Pool을 무시하고 Heap에 새 객체 생성.
