## Q01

```java
class Static {
    public int a = 20;
    static int b = 0;
}

public class Main {
    public static void main(String[] args) {
        int a;
        a = 10;
        Static.b = a;

        Static st = new Static();

        System.out.println(Static.b++);
        System.out.println(st.b);
        System.out.println(a);
        System.out.print(st.a);
    }
}
```

### 핵심 개념

| 구분 | 설명 |
|------|------|
| `static` 변수 | 클래스에 하나만 존재. 모든 인스턴스가 공유. 클래스명으로 접근 가능 (`Static.b`) |
| 인스턴스 변수 | 객체마다 독립적으로 존재 (`st.a`) |
| 후위 증가 (`b++`) | 현재 값을 먼저 사용한 뒤 증가 |

---

### 단계별 풀이

**① 변수 초기화**

```
Static.b = 0   (클래스 로딩 시 static 변수 초기화)
```

**② `a = 10`, `Static.b = a`**

```
지역변수 a = 10
Static.b = 10
```

**③ `Static st = new Static()`**

```
st.a = 20  (인스턴스 변수, 새 객체마다 독립)
st.b       → Static.b 참조 (static이므로 클래스 공유) = 10
```

**④ `System.out.println(Static.b++)`**

```
후위 증가: 현재 값(10)을 출력 → 그 다음 b를 11로 증가
출력: 10
Static.b = 11
```

**⑤ `System.out.println(st.b)`**

```
st.b는 static 변수이므로 Static.b와 동일
Static.b = 11
출력: 11
```

**⑥ `System.out.println(a)`**

```
지역변수 a = 10 (Static.b와 무관)
출력: 10
```

**⑦ `System.out.print(st.a)`**

```
st.a는 인스턴스 변수 = 20
출력: 20
```

---

### 정답

```
10
11
10
20
```

## Q02

```c
#include <stdio.h>

int main() {
    char a[] = "Art";
    char* p = NULL;
    p = a;

    printf("%s\n", a);
    printf("%c\n", *p);
    printf("%c\n", *a);
    printf("%s\n", p);

    for (int i = 0; a[i] != '\0'; i++)
        printf("%c", a[i]);
}
```

### 핵심 개념

| 표현 | 의미 |
|------|------|
| `a` | 배열 이름 = 첫 번째 원소의 주소 |
| `p = a` | 포인터 p가 a[0]을 가리킴 |
| `*p` | p가 가리키는 값 = a[0] = `'A'` |
| `*a` | a[0] = `'A'` (`*p`와 동일) |
| `%s` | 주소부터 `'\0'`까지 문자열 출력 |
| `%c` | 문자 하나 출력 |

---

### 메모리 구조

```
인덱스:  [0]  [1]  [2]  [3]
a[]  :   'A'  'r'  't'  '\0'
          ↑
          p (p = a → a[0] 주소)
```

---

### 단계별 풀이

**① `printf("%s\n", a)`**
```
a = 배열 시작 주소 → 'A'부터 '\0' 직전까지 출력
출력: Art
```

**② `printf("%c\n", *p)`**
```
p = a → *p = a[0] = 'A'
출력: A
```

**③ `printf("%c\n", *a)`**
```
*a = a[0] = 'A'  (*p와 완전히 동일)
출력: A
```

**④ `printf("%s\n", p)`**
```
p = a와 같은 주소 → 'A'부터 '\0' 직전까지 출력
출력: Art
```

**⑤ for 루프**
```
i=0: a[0]='A' → 출력 A
i=1: a[1]='r' → 출력 r
i=2: a[2]='t' → 출력 t
i=3: a[3]='\0' → 조건 거짓, 종료
→ 줄바꿈 없이 Art 출력
```

## Q10

( )은/는 TCP/IP에서 IP 패킷을 처리할 때 발생되는 문제를 알려주는 프로토콜이다.

( ) 프로토콜은 보통 다른 호스트나 게이트웨이와 연결된 네트워크에 문제가 있는지 확인하기 위한 목적으로 주로 사용된다.

( )을/를 이용한 공격에는 ( ) Flooding가 있는데 ping 명령어를 통한 ( ) 패킷을 연속적으로 계속 보내어 서버의 요청에 응답으로 인한 다른 작업을 하지 못하도록 하는 공격이다.

### 풀이

**① 첫 번째 빈칸 — "IP 패킷 처리 시 문제를 알려주는 프로토콜"**

IP는 비신뢰성·비연결성 프로토콜이라 오류가 발생해도 스스로 알리지 못한다.  
이때 오류 메시지와 상태 정보를 전달하는 역할을 하는 것이 **ICMP**이다.

**② 두 번째 빈칸 — "네트워크 문제 확인 목적"**

`ping` 명령어가 바로 ICMP를 활용한 것이다.  
`ping`은 ICMP Echo Request를 보내고 Echo Reply를 받아 연결 상태를 확인한다.

**③ 세 번째·네 번째·다섯 번째 빈칸 — "ICMP를 이용한 공격"**

ICMP Flooding: ping을 이용해 ICMP 패킷을 대량으로 연속 전송 → 서버가 응답 처리로 인해 다른 작업 불가 → **DoS(서비스 거부) 공격**의 일종

### 관련 개념 정리

| 항목 | 내용 |
|------|------|
| ICMP 계층 | 네트워크 계층 (OSI 3계층) — IP와 같은 계층 |
| 주요 메시지 | Echo Request/Reply (ping), Destination Unreachable, Time Exceeded |
| ping 동작 | Echo Request 전송 → Echo Reply 수신 → 응답 시간(RTT) 측정 |
| ICMP Flooding | 대량의 ping 패킷으로 서버 자원 고갈 → DoS 공격 |
| 방어 방법 | 방화벽에서 ICMP 패킷 차단 또는 속도 제한(Rate Limiting) |

### 정답

**ICMP** (Internet Control Message Protocol)

## Q11

- 다른 무언가와 이어지는 인터페이스 역할을 하는 클래스를 의미한다.
- 실제 객체를 호출하면 행위를 중간에 가로채서 다른 동작을 수행하는 객체로 변경한다.
- 객체를 정교하게 제어해야 하거나 객체 참조가 필요한 경우 사용한다.
- 분리된 객체를 위임함으로써 대리 작업을 중간 단계에 삽입할 수도 있으며 분리된 객체를 동적으로 연결함으로써 객체의 실행 시점을 관리할 수도 있다.

### 풀이

**키워드 분석**

| 설명의 키워드 | 의미 |
|-------------|------|
| 인터페이스 역할을 하는 클래스 | 클라이언트는 실제 객체 대신 이 클래스를 통해 접근 |
| 행위를 **중간에 가로채서** 다른 동작 수행 | 실제 객체 앞에 **대리인**이 존재 |
| 객체를 **정교하게 제어** | 접근 제어, 권한 검사, 캐싱 등 부가 기능 수행 |
| **대리 작업** 삽입, **실행 시점** 관리 | 지연 초기화(Lazy Initialization) 등 |

→ 모두 **"대리인"** 이라는 개념을 가리킨다.

**구조**

```
클라이언트 → [Proxy] → 실제 객체(Real Subject)
                ↑
        중간에서 제어·가로채기·위임
```

**GoF 23가지 패턴 분류**

| 분류 | 패턴 |
|------|------|
| 생성(Creational) | Singleton, Factory Method, Abstract Factory, Builder, Prototype |
| **구조(Structural)** | **Proxy**, Adapter, Bridge, Composite, Decorator, Facade, Flyweight |
| 행위(Behavioral) | Observer, Strategy, Command, Iterator, Template Method 등 |

→ Proxy는 **구조(Structural) 패턴**

**혼동하기 쉬운 패턴 구분**

| 패턴 | 핵심 목적 |
|------|----------|
| **Proxy** | 실제 객체에 대한 **접근 제어** (대리인) |
| Decorator | 객체에 **기능을 동적으로 추가** (래핑) |
| Adapter | **인터페이스 변환** (호환성) |
| Facade | 복잡한 서브시스템을 **단순한 인터페이스**로 제공 |

### 정답

**Proxy (프록시) 패턴** — 구조(Structural) 패턴

## Q12

| 구분 | 내용 |
|------|------|
| ( 1 ) | 셀 수 있는 수량의 순서 있는 열거. 테이블에서의 행. 중복 허용 가능 |
| ( 2 ) | 어느 한 시점에 릴레이션의 내용(상태), 저장된 데이터 전체. 릴레이션 외연(Relation Extension) |
| ( 3 ) | 특정 데이터 집합의 유니크(Unique)한 값의 개수. 특정 컬럼의 중복 수치를 나타내는 지표 |

### 풀이

**(1) "테이블에서의 행", "순서 있는 열거", "중복 허용"**

관계형 DB에서 테이블의 **행(row) = 튜플(Tuple)**  
파이썬의 tuple처럼 순서가 있고, 동일한 값이 여러 행에 존재할 수 있다(중복 허용).

**(2) "한 시점의 릴레이션 내용(상태) 전체", "릴레이션 외연"**

릴레이션은 크게 두 가지로 구분된다:

| 용어 | 의미 |
|------|------|
| 릴레이션 스키마 (내연, Intension) | 릴레이션의 구조·틀 (변하지 않음) |
| **릴레이션 인스턴스** (외연, Extension) | 특정 시점에 저장된 데이터 전체 (변함) |

"릴레이션 외연(Relation Extension)" = **릴레이션 인스턴스**

**(3) "유니크한 값의 개수", "컬럼의 중복 수치 지표"**

**카디널리티(Cardinality)**: 특정 컬럼에서 중복을 제외한 고유값의 수

```
예시) 성별 컬럼: 남, 여 → 카디널리티 = 2  (낮음 = 중복 많음)
     학번 컬럼: 모두 고유 → 카디널리티 = 행 수 (높음 = 중복 없음)
```

> ※ 혼동 주의: 릴레이션 전체 **행의 수**도 카디널리티라 부르는 경우가 있음.  
> 이 문제는 "컬럼의 유니크한 값 개수"로 묻고 있으므로 동일하게 **카디널리티**가 정답.

### 관련 DB 용어 정리

| 용어 | 의미 |
|------|------|
| 튜플 (Tuple) | 행(row) |
| 속성 (Attribute) | 열(column) |
| 카디널리티 (Cardinality) | 튜플(행)의 수 / 컬럼의 고유값 수 |
| 디그리 (Degree) | 속성(열)의 수 |
| 릴레이션 인스턴스 | 특정 시점의 릴레이션 전체 데이터 |
| 도메인 (Domain) | 각 속성이 가질 수 있는 값의 범위 |

### 정답

- (1) **튜플 (Tuple)**
- (2) **릴레이션 인스턴스 (Relation Instance)**
- (3) **카디널리티 (Cardinality)**

## Q14

```java
public class Sort {
    public static void swap(int[] arr, int idx1, int idx2) {
        int temp = arr[idx1];
        arr[idx1] = arr[idx2];
        arr[( 1 )] = temp;
    }
    public static void Usort(int[] array, int length) {
        for (int i = 0; i < length; i++) {
            for (int j = 0; j < length - i - 1; j++) {
                if (array[j] > array[j + 1]) {
                    swap(array, j, j + 1);
                }
            }
        }
    }
    public static void main(String[] args) {
        int[] item = new int[]{5, 3, 8, 1, 2, 7};
        int nx = 6;
        Usort(item, ( 2 ));
        for (int data : item) {
            System.out.print(data + " ");
        }
    }
}
```

### 풀이

**빈칸 (1) — swap 메서드**

두 값을 교환하는 로직:
```
temp    = arr[idx1]   // idx1 값 임시 저장
arr[idx1] = arr[idx2] // idx2 값을 idx1 자리에 덮어씀
arr[???]  = temp      // 임시 저장해둔 원래 idx1 값을 idx2 자리에 넣음
```
→ (1) = **idx2**

**빈칸 (2) — Usort 호출**

```java
int nx = 6;           // item 배열의 길이
Usort(item, ( 2 ));   // length 자리에 배열 길이를 넘겨야 함
```
→ (2) = **nx**

## Q17

```java
abstract class Vehicle {
    String name;
    abstract public String getName(String val);

    public String getName() {
        return "Vehicle name: " + name;
    }
}
class Car extends Vehicle {
    public Car(String val) {
        name = super.name = val;
    }
    public String getName(String val) {
        return "Car name:" + val;
    }
    public String getName(byte val[]) {
        return "Car name:" + val;
    }
}
public class Main {
    public static void main(String[] args) {
        Vehicle obj = new Car("Spark");
        System.out.println(obj.getName());
    }
}
```

### 핵심 개념

| 개념 | 설명 |
|------|------|
| 추상 클래스 | `abstract` 키워드. 직접 인스턴스 생성 불가. 추상 메서드와 일반 메서드 모두 가질 수 있음 |
| 오버라이딩 | 부모의 메서드를 자식이 **같은 시그니처**로 재정의 |
| 오버로딩 | **같은 이름**, 다른 매개변수로 메서드 여러 개 정의 |
| 다형성 | `Vehicle obj = new Car(...)` — 선언은 부모 타입, 실제 객체는 자식 |

### 단계별 풀이

**① `Vehicle obj = new Car("Spark")`**

Car 생성자 실행:
```java
name = super.name = val;
// super.name(Vehicle의 name 필드) = "Spark"
// name(Car에서 상속받은 같은 필드) = "Spark"
// → Vehicle의 name 필드가 "Spark"로 설정됨
```

**② `obj.getName()` — 어떤 메서드가 호출되는가?**

각 클래스의 `getName` 메서드 목록:

| 클래스 | 메서드 시그니처 | 종류 |
|--------|---------------|------|
| Vehicle | `getName()` | 일반 메서드 ✓ |
| Vehicle | `getName(String val)` | 추상 메서드 |
| Car | `getName(String val)` | 오버라이딩 |
| Car | `getName(byte[] val)` | 오버로딩 |

`obj.getName()` → **인수 없는** `getName()` 호출  
Car에는 `getName()`이 **없음** → Vehicle의 `getName()` 실행

```java
// Vehicle.getName() 실행
return "Vehicle name: " + name;
// name = "Spark"
// → "Vehicle name: Spark"
```

### 만약 인수가 있었다면?

`obj.getName("Spark")` 처럼 String 인수가 있었다면:
- Vehicle의 `getName(String val)` → **추상 메서드** (구현 없음)
- Car의 `getName(String val)` → Vehicle을 **오버라이딩** ✓

런타임 다형성에 의해 실제 객체인 Car의 메서드가 실행된다.

```java
// Car.getName(String val) 실행
return "Car name:" + val;  // → "Car name:Spark"
```

**비교 정리**

| 호출 | 실행되는 메서드 | 결과 |
|------|---------------|------|
| `obj.getName()` | Vehicle의 `getName()` | `Vehicle name: Spark` |
| `obj.getName("Spark")` | Car의 `getName(String val)` | `Car name:Spark` |

> Car가 **오버라이딩한 메서드** → Car 버전 실행  
> Car가 **오버라이딩 안 한 메서드** → 부모(Vehicle) 버전 실행

### 정답

```
Vehicle name: Spark
```

## Q20

```java
class Parent {
    int x = 100;
    Parent() { this(500); }
    Parent(int x) { this.x = x; }
    int getX() { return x; }
}
class Child extends Parent {
    int x = 4000;
    Child() { this(5000); }
    Child(int x) { this.x = x; }
}
public class Main {
    public static void main(String[] args) {
        Child obj = new Child();
        System.out.println(obj.getX());
    }
}
```

### 핵심 개념

| 개념 | 설명 |
|------|------|
| `this(...)` | **같은 클래스**의 다른 생성자 호출 |
| `super()` | **부모 클래스**의 생성자 호출 |
| 암묵적 `super()` | 생성자 첫 줄에 `this()` 또는 `super()`가 없으면 컴파일러가 자동으로 `super()` 삽입 |
| 필드 숨김 | Parent와 Child 모두 `int x` 선언 → **별개의 두 필드** 존재 |

### 두 x 필드 구분

```
Parent 객체 영역:  int x  (← getX()가 참조하는 x)
Child  객체 영역:  int x  (← Child 생성자의 this.x)
```

Parent에 `getX()`가 정의되어 있으므로 **Parent의 x**를 반환한다.

### 생성자 호출 순서

```
new Child()
  └─ Child()
       └─ this(5000) → Child(int x = 5000)
              └─ [암묵적 super()] → Parent()
                       └─ this(500) → Parent(int x = 500)
                                └─ Parent.x = 500  ✓ 확정
              └─ Child.x = 5000  ✓ 확정
```

### 단계별 풀이

**① `new Child()` → `Child()`**
```java
Child() { this(5000); }  // Child(5000) 호출
```

**② `Child(5000)` — 첫 줄에 this/super 없음 → 컴파일러가 super() 자동 삽입**
```java
Child(int x) {
    // [super() 자동 삽입] → Parent() 실행
    this.x = x;  // 나중에 실행
}
```

**③ `Parent()` 실행**
```java
Parent() { this(500); }  // Parent(500) 호출
```

**④ `Parent(500)` 실행**
```java
Parent(int x) { this.x = x; }  // Parent.x = 500
```

**⑤ ③④ 완료 후 `Child(5000)` 본문 실행**
```java
this.x = 5000;  // Child.x = 5000
```

**⑥ `obj.getX()` — Parent에 정의된 메서드**
```java
int getX() { return x; }  // Parent의 x 반환 → 500
```

### 만약 Child에도 getX()가 있었다면?

```java
class Child extends Parent {
    int x = 4000;
    Child() { this(5000); }
    Child(int x) { this.x = x; }

    int getX() { return x; }  // 오버라이딩 추가된 경우
}
```

`obj.getX()` → Child의 `getX()` 실행 → Child의 x = **5000**

**비교 정리**

| 상황 | 실행 메서드 | 참조하는 x | 결과 |
|------|-----------|-----------|------|
| Child에 `getX()` 없음 (현재 문제) | Parent의 `getX()` | Parent.x = 500 | **500** |
| Child에 `getX()` 있음 | Child의 `getX()` | Child.x = 5000 | **5000** |

> 오버라이딩된 메서드는 항상 **실제 객체의 클래스(Child) 버전**이 실행된다.

### 정답

```
500
```

## Q15

```python
a = {'한국', '중국', '일본'}
a.add('베트남')
a.add('중국')
a.remove('일본')
a.update({'홍콩', '한국', '태국'})
print(a)
```

### 핵심 개념 — 파이썬 자료형 구분

`{ }` 안에 값만 있으면 **set**, `키: 값` 형태면 **dict**

| 자료형 | 선언 | 순서 | 중복 |
|--------|------|------|------|
| `list`  | `[1, 2, 3]`   | O | O |
| `tuple` | `(1, 2, 3)`   | O | O (수정 불가) |
| `set`   | `{1, 2, 3}`   | X | **X** |
| `dict`  | `{'a': 1}`    | O | 키 중복 X |

→ 이 문제의 `a = {'한국', '중국', '일본'}` 은 **set**

### 딕셔너리 (dict)

**키(key) - 값(value)** 쌍으로 데이터를 저장하는 자료형

```python
d = {'이름': '홍길동', '나이': 20, '학과': '컴퓨터'}

d['이름']      # '홍길동'  ← 키로 값에 접근
d['나이'] = 21 # 값 수정
d['학년'] = 3  # 새 키-값 추가
del d['학과']  # 삭제
```

| 특징 | 설명 |
|------|------|
| 키(key) | 중복 불가, 수정 불가 (immutable) |
| 값(value) | 중복 가능, 수정 가능 |
| 순서 | Python 3.7부터 삽입 순서 유지 |

**주요 메서드**

| 메서드 | 동작 |
|--------|------|
| `d.keys()` | 키 목록 반환 |
| `d.values()` | 값 목록 반환 |
| `d.items()` | (키, 값) 쌍 목록 반환 |
| `d.get(key)` | 키로 값 조회 (없으면 None 반환, KeyError 없음) |

### set 주요 메서드

| 메서드 | 동작 | 중복 처리 |
|--------|------|----------|
| `add(x)` | 원소 1개 추가 | 이미 있으면 **무시** |
| `remove(x)` | 원소 1개 제거 | 없으면 **KeyError** |
| `update(iterable)` | 여러 원소 추가 (합집합) | 중복은 **무시** |

> set은 **순서 없음**, **중복 없음**

### 단계별 풀이

```
초기:              {한국, 중국, 일본}

add('베트남'):     {한국, 중국, 일본, 베트남}

add('중국'):       {한국, 중국, 일본, 베트남}   ← 중국 이미 존재 → 무시

remove('일본'):    {한국, 중국, 베트남}

update({'홍콩', '한국', '태국'}):
                   홍콩 → 추가
                   한국 → 이미 존재, 무시
                   태국 → 추가
                   {한국, 중국, 베트남, 홍콩, 태국}
```

### 정답

```
{'한국', '중국', '베트남', '홍콩', '태국'}
```

> ※ set은 순서가 없으므로 출력 시 원소 순서는 달라질 수 있음.  
> 시험에서는 **원소 5개가 모두 포함**되어 있으면 정답.
