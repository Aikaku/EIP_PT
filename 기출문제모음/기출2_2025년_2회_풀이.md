## Q02. 데이터베이스 릴레이션 구성 요소

> 릴레이션(Relation)에서 열(Column)을 의미하며 데이터 항목의 속성(Attribute) 또는 특성을 나타낸다.
> 각 열은 고유한 이름을 가지며 특정 도메인(Domain)에서 정의된 값을 갖는다.
> 이 개념은 파일 구조에서의 필드(Field)에 해당하며 릴레이션에서 행(Row, Tuple)의 구성 요소가 된다.
>
> \[보기\] ㄱ. Cardinality ㄴ. Domain ㄷ. Attribute ㅁ. Degree ㅂ. Schema ㅅ. Tuple

**정답**: `ㄷ. Attribute`

---

### 풀이

설명의 핵심 키워드: **열(Column)**, **속성**, **필드(Field)에 해당**
→ 이는 모두 **Attribute(속성)** 를 설명하는 표현

---

### 번외 — 릴레이션 구성 요소 전체 정리

| 용어 | 설명 | 파일 구조 대응 |
|------|------|--------------|
| **Attribute (속성)** | 열(Column). 데이터 항목의 특성 | 필드(Field) |
| **Tuple (튜플)** | 행(Row). 하나의 데이터 레코드 | 레코드(Record) |
| **Domain (도메인)** | 속성이 가질 수 있는 값의 범위 | - |
| **Degree (차수)** | 속성(열)의 **수** | - |
| **Cardinality (카디널리티)** | 튜플(행)의 **수** | - |
| **Schema (스키마)** | 릴레이션의 구조 정의 (속성 이름·타입) | - |

**예시 — "학생" 릴레이션**

| 학번 | 이름 | 전공 |
|------|------|------|
| 2001 | 홍길동 | 컴퓨터공학 |
| 2002 | 김철수 | 경영학 |

- **Attribute**: 학번, 이름, 전공 (열 3개)
- **Tuple**: 홍길동 행, 김철수 행 (행 2개)
- **Degree**: 3 (속성 수)
- **Cardinality**: 2 (튜플 수)
- **Domain**: 이름 속성의 도메인 = 문자열 집합

> **암기 포인트**: Degree(차수) = **열 수**, Cardinality = **행 수**

## Q04. 스케줄링 알고리즘

> (1) CPU burst 시간이 짧은 프로세스를 우선적으로 처리하는 스케줄링 방식이다. "Shortest Next CPU Burst"라고도 불리며 선점형 또는 비선점형으로 구현될 수 있다.
>
> (2) 위의 스케줄링 방식을 선점형으로 구현한 형태로 실행 중인 프로세스보다 더 짧은 burst 시간을 가진 프로세스가 도착하면 현재 CPU를 선점한다.

**정답**:
- (1) **SJF (Shortest Job First)**
- (2) **SRT (Shortest Remaining Time)**

---

### 풀이

| 구분 | SJF | SRT |
|------|-----|-----|
| 전체 명칭 | Shortest Job First | Shortest Remaining Time |
| 선점 여부 | **비선점형** | **선점형** |
| 기준 | CPU burst 시간이 짧은 순 | 남은 실행 시간이 더 짧은 프로세스가 오면 선점 |
| 특징 | 이미 실행 중이면 끝날 때까지 실행 | 더 짧은 프로세스 도착 시 즉시 CPU 빼앗김 |
| 단점 | 긴 프로세스 기아(Starvation) 가능 | 긴 프로세스 기아 가능 + 잦은 문맥 교환 |

---

### 번외 — 주요 스케줄링 알고리즘 전체 비교

| 알고리즘 | 선점 | 기준 | 특징 |
|---------|------|------|------|
| **FCFS** | 비선점 | 도착 순서 | 가장 단순, 호위 효과(Convoy Effect) |
| **SJF** | 비선점 | CPU burst 짧은 순 | 평균 대기시간 최소 |
| **SRT** | 선점 | 남은 시간 짧은 순 | SJF의 선점형 버전 |
| **HRN** | 비선점 | 우선순위 = `(대기시간 + 실행시간) / 실행시간` | SJF의 기아 보완 |
| **RR** | 선점 | 시간 할당량(Time Quantum) 순환 | 시분할 시스템, 공평성 |
| **Priority** | 선점/비선점 | 우선순위 숫자 | 낮은 숫자 = 높은 우선순위 (보통) |

> **암기 포인트**: SJF(비선점) ↔ SRT(선점) 쌍으로 묶어서 기억

## Q05. Java — 참조 전달 vs 값 전달 (Pass by Value)

```java
public class Main {
    public static void change(String[] data, String s){
        data[0] = s;
        s = "Z";
    }
    
    public static void main(String[] args) {
        String data[] = { "A" };
        String s = "B";
        
        change(data, s);
        System.out.print(data[0] + s);
    }
}
```

**정답**: `BB`

---

### 풀이

**① main() 초기 상태**

```
data → ["A"]   (배열 참조)
s    → "B"     (String 참조)
```

**② change(data, s) 호출**

Java는 **항상 값에 의한 전달(Pass by Value)** — 참조 타입도 참조값(주소)의 복사본을 넘김

```
change의 data → main의 data와 같은 배열을 가리킴 (복사된 참조)
change의 s    → "B"를 가리킴 (복사된 참조)
```

**③ change() 내부 실행**

```java
data[0] = s;   // 배열 내부 값을 "B"로 변경 → 원본 배열에 반영됨
s = "Z";       // 지역 매개변수 s만 "Z"로 재할당 → main의 s에는 영향 없음
```

| 코드 | 변화 | main 원본 영향 |
|------|------|--------------|
| `data[0] = s` | 배열 **내부 값** 수정 | **반영됨** (같은 배열 가리킴) |
| `s = "Z"` | 지역 변수 **재할당** | **반영 안 됨** (복사본만 바뀜) |

**④ change() 종료 후 main() 상태**

```
data[0] → "B"  (change 내부에서 변경됨)
s       → "B"  (change의 재할당은 지역에서만 적용)
```

**⑤ 출력**

```java
System.out.print(data[0] + s);
// "B" + "B" = "BB"
```

---

### 번외 — Java Pass by Value 핵심 정리

| 전달 타입 | 동작 | 원본 영향 |
|----------|------|---------|
| 기본 자료형 (int, char 등) | 값 자체를 복사 | **없음** |
| 배열·객체 (참조 타입) — **내부 수정** | 같은 객체를 수정 | **있음** |
| 배열·객체 (참조 타입) — **재할당** | 지역 참조만 변경 | **없음** |

> Java는 C++의 `&` 참조 전달과 달리, **항상 값(value)을 복사**해서 전달한다.
> 참조 타입의 경우 그 값이 "주소값"이므로, 주소를 통해 내부를 수정하면 원본에 반영된다.

## Q06. 서브넷 마스크 — 네트워크 주소 & 호스트 수

> IP 주소: `223.13.234.132`, 서브넷 마스크: `255.255.255.192`
>
> ① 이 호스트가 속한 네트워크 주소는 223.13.234.( ? )이다.
>
> ② 이 네트워크에서 사용 가능한 호스트 수는 ( ? )개이다. (네트워크·브로드캐스트 제외)

**정답**:
- ① **128**
- ② **62**

---

### 풀이

앞 세 옥텟(223.13.234)은 서브넷 마스크가 255로 동일하므로 마지막 옥텟만 계산

**① 네트워크 주소 — IP AND 서브넷 마스크**

```
IP 마지막 옥텟:       132 = 1000 0100
서브넷 마스크 마지막:  192 = 1100 0000
                           AND (둘 다 1인 자리만 1)
네트워크 주소:              1000 0000 = 128
```

→ 네트워크 주소 = `223.13.234.128`

**② 사용 가능한 호스트 수**

```
서브넷 마스크 192 = 1100 0000
                   ^^       ← 네트워크 비트 2개
                     ^^^^^^ ← 호스트 비트 6개
```

| 계산 | 값 |
|------|-----|
| 호스트 비트 수 | 6 |
| 총 주소 수 | 2⁶ = 64 |
| 네트워크 주소 제외 | -1 |
| 브로드캐스트 주소 제외 | -1 |
| **사용 가능한 호스트 수** | **62** |

**주소 범위 확인:**

| 구분 | 주소 | 이진수 (마지막 옥텟) |
|------|------|-------------------|
| 네트워크 주소 | 223.13.234.**128** | 1000 0000 |
| 첫 번째 호스트 | 223.13.234.**129** | 1000 0001 |
| 마지막 호스트 | 223.13.234.**190** | 1011 1110 |
| 브로드캐스트 | 223.13.234.**191** | 1011 1111 |

---

### 번외 — 서브넷 마스크 계산 공식

| 서브넷 마스크 | CIDR | 호스트 비트 | 총 주소 | 사용 가능 호스트 |
|-------------|------|-----------|--------|--------------|
| 255.255.255.0 | /24 | 8 | 256 | 254 |
| 255.255.255.128 | /25 | 7 | 128 | 126 |
| **255.255.255.192** | **/26** | **6** | **64** | **62** |
| 255.255.255.224 | /27 | 5 | 32 | 30 |
| 255.255.255.240 | /28 | 4 | 16 | 14 |

> **공식**: 사용 가능 호스트 수 = **2ⁿ - 2** (n = 호스트 비트 수)

## Q09. Java — 람다식 + 함수형 인터페이스 + 예외 처리

```java
public class Main {

    static interface F {
        int apply(int x) throws Exception;
    }

    public static int run(F f) {
        try {
            return f.apply(3);
        } catch (Exception e) {
            return 7;
        }
    }

    public static void main(String[] args) {

        F f = (x) -> {
            if (x > 2) {
                throw new Exception();
            }
            return x * 2;
        };

        System.out.print(run(f) + run((int n) -> n + 9));
    }
}
```

**정답**: `19`

---

### 풀이

**① `run()` 메서드 구조 파악**

```java
public static int run(F f) {
    try {
        return f.apply(3);   // 항상 x = 3으로 호출
    } catch (Exception e) {
        return 7;            // 예외 발생 시 7 반환
    }
}
```
→ `run()`은 항상 **x = 3** 으로 `apply`를 호출하고, 예외 발생 시 **7** 반환

---

**② 첫 번째 호출: `run(f)`**

```java
F f = (x) -> {
    if (x > 2) throw new Exception();  // x=3 → 3 > 2 → Exception 발생!
    return x * 2;
};
```

- x = 3, 3 > 2 → `Exception` 던짐
- `catch(Exception e)` → **return 7**

→ `run(f)` = **7**

---

**③ 두 번째 호출: `run((int n) -> n + 9)`**

```java
(int n) -> n + 9
```

- x = 3 → 3 + 9 = 12
- 예외 없음 → **return 12**

→ `run((int n) -> n + 9)` = **12**

---

**④ 최종 출력**

```java
System.out.print(run(f) + run((int n) -> n + 9));
//               7       +       12              = 19
```

---

### 번외 — 람다식 & 함수형 인터페이스

**함수형 인터페이스**: 추상 메서드가 **딱 1개**인 인터페이스 → 람다식으로 구현 가능

```java
// 인터페이스 정의
interface F {
    int apply(int x) throws Exception;
}

// 람다식으로 구현 (익명 클래스 대신)
F f = (x) -> x * 2;
F f = (int x) -> { return x * 2; };  // 동일한 표현
```

**람다식 문법:**
```java
(매개변수) -> 표현식
(매개변수) -> { 실행문; return 값; }
```

| 표현 | 의미 |
|------|------|
| `(x) -> x * 2` | x를 받아 x*2 반환 |
| `(int n) -> n + 9` | n을 받아 n+9 반환 |
| `(x) -> { if(...) throw ...; return x; }` | 블록 람다 (여러 줄) |
