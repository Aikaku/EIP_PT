# 디자인 패턴 단답형 문제

1. 요청을 객체 형태로 캡슐화하여 저장하거나 취소할 수 있도록 하는 패턴은?

2. 객체를 대리하여 접근을 제어하는 패턴은?

3. 구현부와 추상부를 분리하여 독립적으로 확장할 수 있도록 하는 패턴은?

4. 원본 객체를 복제하여 객체를 생성하는 패턴은?

5. 객체의 상태에 따라 동일한 동작을 다르게 처리하는 패턴은?

6. 복잡한 서브 시스템을 하나의 인터페이스로 제공하는 패턴은?

7. 자료 구조를 순차적으로 접근할 수 있도록 하는 패턴은?

8. 인터페이스가 맞지 않는 클래스를 사용할 수 있도록 변환하는 패턴은?

9. 객체 간의 결합을 통해 기능을 동적으로 추가하는 패턴은?

10. 객체 간 복잡한 상호작용을 하나의 객체로 캡슐화하는 패턴은?

11. 상위 클래스에서 알고리즘의 골격을 정의하고 하위 클래스에서 세부 내용을 구현하는 패턴은?

12. 여러 객체를 트리 구조로 구성하여 동일하게 다루는 패턴은?

13. 하나의 객체만 생성하여 공유하는 패턴은?

14. 언어의 문법을 표현하는 패턴은?

15. 관련 객체들을 그룹으로 생성하는 패턴은?

16. 객체의 상태를 저장했다가 이전 상태로 복원하는 패턴은?

17. 인스턴스를 공유하여 메모리를 절약하는 패턴은?

18. 객체 생성을 서브 클래스에 위임하는 패턴은?

19. 요청을 처리할 수 있는 객체를 연결하여 순차적으로 전달하는 패턴은?

20. 데이터 구조와 처리 기능을 분리하는 패턴은?

21. 상태 변화가 발생하면 관련 객체들에게 자동으로 알리는 패턴은?

22. 작은 객체를 조합하여 큰 객체를 생성하는 패턴은?

23. 서로 다른 알고리즘을 캡슐화하여 교체할 수 있는 패턴은?

---

# 정답

1. 커맨드(Command)
2. 프록시(Proxy)
3. 브리지(Bridge)
4. 프로토타입(Prototype)
5. 상태(State)
6. 퍼싸드(Facade)
7. 반복자(Iterator)
8. 어댑터(Adapter)
9. 데코레이터(Decorator)
10. 중재자(Mediator)
11. 템플릿 메소드(Template Method)
12. 컴포지트(Composite)
13. 싱글톤(Singleton)
14. 인터프리터(Interpreter)
15. 추상 팩토리(Abstract Factory)
16. 메멘토(Memento)
17. 플라이웨이트(Flyweight)
18. 팩토리 메소드(Factory Method)
19. 책임 연쇄(Chain of Responsibility)
20. 방문자(Visitor)
21. 옵서버(Observer)
22. 빌더(Builder)
23. 전략(Strategy)
