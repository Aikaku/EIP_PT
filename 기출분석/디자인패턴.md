# 디자인 패턴 단답형 문제

1. 연관된 서브 클래스를 묶어 한 번에 교체할 수 있으며, 구체적인 클래스에 의존하지 않고 인터페이스를 통해 서로 연관된 객체들의 그룹을 생성하는 패턴은?

2. 객체의 상태를 캡슐화하고 이를 참조하는 방식으로 객체의 상태에 따라 동일한 동작을 다르게 처리하는 패턴은?

3. 기존 클래스를 이용하고 싶지만 인터페이스가 일치하지 않을 때, 호환성이 없는 클래스들의 인터페이스를 변환해 주는 패턴은?

4. 하나의 객체를 생성하면 어디서든 참조할 수 있으며, 클래스 내에서 인스턴스가 하나뿐임을 보장하는 패턴은?

5. 객체의 생성 과정과 표현 방법을 분리하여 동일한 객체 생성에서도 서로 다른 결과를 만들어 낼 수 있는 패턴은?

6. 요청을 처리할 수 있는 객체가 둘 이상 존재하여 하나가 처리하지 못하면 다음 객체로 책임이 넘어가는 패턴은?

7. 객체들을 트리 구조로 구성하여 복합 객체와 단일 객체를 구분 없이 다룰 수 있도록 하는 패턴은?

8. 언어의 문법 표현을 정의하며 SQL이나 통신 프로토콜 등을 개발할 때 사용하는 패턴은?

9. 상위 클래스에서 인터페이스만 정의하고 실제 객체 생성은 서브 클래스가 담당하도록 하는 패턴은?

10. 객체 간의 결합을 통해 임의의 객체에 부가적인 기능을 동적으로 추가하는 패턴은?

11. 복잡한 서브 클래스들의 기능을 간편하게 사용할 수 있도록 상위 인터페이스를 제공하는 패턴은?

12. 자료 구조와 같이 접근이 잦은 객체에 대해 내부 표현을 노출하지 않고 동일한 인터페이스로 순차 접근할 수 있게 하는 패턴은?

13. 원본 객체를 복제하는 방법으로 객체를 생성하며, 생성 비용이 큰 경우 주로 사용하는 패턴은?

14. 요청을 객체 형태로 캡슐화하여 재사용하거나 취소할 수 있도록 요청 정보를 저장하는 패턴은?

15. 객체의 내부 상태를 저장하였다가 이후 요청에 따라 특정 시점의 상태로 되돌릴 수 있도록 하는 패턴은?

16. 동일한 계열의 알고리즘을 각각 캡슐화하여 상호 교환할 수 있도록 정의하는 패턴은?

17. 클래스나 객체들의 복잡한 상호작용을 하나의 객체로 캡슐화하여 객체 사이의 의존성을 줄이는 패턴은?

18. 상위 클래스에서 알고리즘의 골격을 정의하고 하위 클래스에서 세부 처리를 구체화하는 구조의 패턴은?

19. 구현부와 추상층을 분리하여 서로 독립적으로 확장할 수 있도록 하는 패턴은?

20. 인스턴스를 가능한 한 공유하여 메모리를 절약하고 다수의 유사 객체를 효율적으로 사용하는 패턴은?

21. 한 객체의 상태가 변화하면 이를 상속받거나 의존하는 다른 객체들에게 변경된 상태를 전달하는 패턴은?

22. 객체의 세부 내용을 숨기고 대리 역할을 수행하여 복잡한 관계를 단순하게 정리하는 패턴은?

23. 각 클래스의 데이터 구조와 처리 기능을 분리하여 별도의 클래스로 구성하고, 각 클래스를 방문하여 기능을 수행하는 패턴은?
