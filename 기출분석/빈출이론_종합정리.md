## 1. C언어 핵심

### 포인터

```c
int a = 10;
int *p = &a;   // p는 a의 주소를 담는 포인터

*p = 20;       // p가 가리키는 곳(a)의 값을 20으로 변경
printf("%d", a); // 20
```

- `&변수` : 변수의 주소
- `*포인터` : 포인터가 가리키는 곳의 값 (역참조)
- `*(p + 1)` : p에서 1칸 앞의 값 (배열에서 다음 원소)

```c
char *p = "KOREA";
printf("%s", p);     // KOREA  (p부터 끝까지 문자열)
printf("%s", p + 1); // OREA   (p+1부터)
printf("%c", *p);    // K      (p가 가리키는 첫 문자)
printf("%c", *(p+3));// E      (4번째 문자)
printf("%c", *p + 4);// O      ('K'=75, 75+4=79='O')  ← 문자 연산 주의
```

### 구조체와 `->`

```c
struct Data {
    int num;
    char c;
};

struct Data d1;
d1.num = 10;         // . 으로 접근 (값 타입)

struct Data *d2 = malloc(sizeof(struct Data));
d2->num = 10;        // -> 로 접근 (포인터 타입)
(*d2).num = 10;      // 위와 동일
```

- **일반 변수** → `.` 연산자
- **포인터 변수** → `->` 연산자

### 재귀 함수

```c
int f(int n) {
    if (n <= 1) return 1;      // 종료 조건
    return n * f(n - 1);       // 재귀 호출
}
// f(5) = 5 * f(4) = 5 * 4 * f(3) = 5*4*3*2*1 = 120
```

팩토리얼 패턴: `f(n) = n * f(n-1)`, f(1)=1, f(0)=1

### static (정적 변수)

```c
void count() {
    static int cnt = 0;   // 최초 1번만 초기화, 이후 값 유지
    cnt++;
    printf("%d ", cnt);
}
count(); // 1
count(); // 2
count(); // 3
```

- `static` 변수는 함수가 끝나도 값이 사라지지 않음
- 일반 지역변수는 함수 호출마다 초기화됨

### 2차원 배열 포인터

```c
int arr[3][3] = {1,2,3, 4,5,6, 7,8,9};
int *parr[2] = {arr[1], arr[2]};
// parr[0] = arr[1] = {4,5,6}
// parr[1] = arr[2] = {7,8,9}

parr[1][1]      // 8  (arr[2][1])
*(parr[1] + 2)  // 9  (arr[2][2])
**parr          // 4  (*parr[0] = arr[1][0])
```

### 완전수 판별 패턴

```c
int test(int n) {
    int sum = 0;
    for (int i = 1; i <= n/2; i++) {
        if (n % i == 0) sum += i;
    }
    return (n == sum) ? 1 : 0;
}
// 완전수: 약수의 합 = 자기 자신 (6=1+2+3, 28=1+2+4+7+14)
// 2~100 사이 완전수: 6 + 28 = 34
```

## 2. Java 핵심

### 다형성과 동적 바인딩

```java
class A {
    void show() { System.out.print("A"); }
    static void sShow() { System.out.print("SA"); }
}
class B extends A {
    void show() { System.out.print("B"); }       // 오버라이딩
    static void sShow() { System.out.print("SB"); } // 숨김(hiding)
}

A obj = new B();   // 선언 타입: A, 실제 타입: B

obj.show();        // B  ← 실제 타입(B)의 메서드 호출 (동적 바인딩)
obj.sShow();       // SA ← 선언 타입(A)의 static 메서드 호출 (정적 바인딩)
```

**핵심 규칙**
- 일반(인스턴스) 메서드: **실제 객체 타입** 기준 (동적 바인딩)
- static 메서드: **선언 타입** 기준 (정적 바인딩)
- 변수(필드): **선언 타입** 기준

```java
class A {
    int x = 10;
    void show() { System.out.print("A메서드"); }
}
class B extends A {
    int x = 20;          // 부모와 같은 이름의 변수 (hiding)
    void show() { System.out.print("B메서드"); }
}

A obj = new B();         // 선언 타입: A,  실제 타입: B

obj.show();   // B메서드  ← 실제 타입(B) 기준 → 동적 바인딩
obj.x;        // 10       ← 선언 타입(A) 기준 → 정적 바인딩
```

> 왜 변수는 선언 타입 기준인가?
> 메서드는 런타임에 실제 객체를 보고 결정하지만,
> 변수는 컴파일 타임에 선언 타입만 보고 이미 결정해버리기 때문.
> 그래서 `A obj`로 선언하면 obj.x는 항상 A의 x(=10)를 가리킴.

**메서드 내부에서 x를 사용하는 경우**

```java
class A {
    int x = 10;
    void show() { System.out.println("A의 show, x=" + x); }  // A의 x
}
class B extends A {
    int x = 20;
    void show() { System.out.println("B의 show, x=" + x); }  // B의 x
}

A obj = new B();

obj.show();   // → B의 show() 실행 (동적 바인딩)
              //   B의 show() 안에서 x는 B의 x = 20
              //   출력: "B의 show, x=20"

obj.x;        // → A의 x = 10 (선언 타입 기준, 외부 접근)
```

> 핵심: 메서드 **외부**에서 `obj.x`로 접근 → 선언 타입(A)의 x  
> 메서드 **내부**에서 그냥 `x` → 그 메서드를 정의한 클래스의 x  
>
> 즉 B의 show()가 호출되면, 그 안의 x는 B의 x(=20)  
> A의 show()가 호출되면, 그 안의 x는 A의 x(=10)

### 생성자 호출 순서

```java
class Parent {
    Parent() { System.out.println("Parent 생성자"); }
}
class Child extends Parent {
    Child() {
        // 여기서 super()가 자동 삽입됨
        System.out.println("Child 생성자");
    }
}
// new Child() 출력:
// Parent 생성자  ← 부모가 먼저 완료
// Child 생성자
```

- 자식 생성자 안에서 `super()`가 첫 줄에 자동 삽입
- 부모에 기본 생성자 없으면 반드시 `super(인자)` 명시해야 함
- 순서: **자식 시작 → 부모 시작 → 부모 완료 → 자식 완료**

### super 사용법

```java
class B extends A {
    void method() {
        super.display();   // 부모 A의 display() 직접 호출
        super.변수;        // 부모 클래스의 필드 접근
    }
}
```

### 오버라이딩 vs 오버로딩

| 구분 | 오버라이딩(Overriding) | 오버로딩(Overloading) |
|------|----------------------|----------------------|
| 위치 | 부모-자식 클래스 간 | 같은 클래스 안 |
| 메서드명 | 동일 | 동일 |
| 매개변수 | **동일** | **다름** (개수 또는 타입) |
| 반환형 | 동일 | 무관 |
| 목적 | 재정의 | 다양한 형태 제공 |

### try-catch-finally

```java
try {
    // 예외 발생 가능 코드
    int result = 10 / 0;  // ArithmeticException 발생
} catch (ArithmeticException e) {
    System.out.print("catch");
} finally {
    System.out.print("finally");  // 예외 여부 상관없이 항상 실행
}
// 출력: catchfinally
```

- `finally`는 **무조건 실행** (return 앞에도 실행)
- 예외 없으면: try → finally
- 예외 있으면: try (일부) → catch → finally

### String 비교

```java
String a = "hello";
String b = "hello";
String c = new String("hello");

a == b       // true  (리터럴은 같은 메모리 참조)
a == c       // false (new로 생성하면 다른 객체)
a.equals(c)  // true  (값 비교)
```

### switch fall-through

```java
int x = 2;
switch(x) {
    case 1: System.out.print("1");
    case 2: System.out.print("2");   // 여기서 시작
    case 3: System.out.print("3");   // break 없으면 계속 실행
    default: System.out.print("D");
}
// 출력: 23D  ← break 없으면 아래로 계속 떨어짐(fall-through)
```

### static 메서드에서 인스턴스 변수 사용 불가

```java
class Person {
    private String name;                 // 인스턴스 변수
    public static String get() {
        return name;                     // 에러! static에서 name 사용 불가
    }
}
```

static 메서드는 객체 없이도 호출 가능 → 아직 `name`이 존재하지 않을 수 있음

### 재귀 (피보나치 변형 주의)

```java
class Child extends Parent {
    int compute(int num) {
        if (num <= 1) return num;
        return compute(num-1) + compute(num-3);  // -3 주의 (일반 피보나치와 다름)
    }
}
// Child로 오버라이딩됐으므로 Parent obj = new Child()도 Child.compute 호출
```

## 3. SQL 핵심

### 기본 SELECT 구조

```sql
SELECT 컬럼명
FROM 테이블명
WHERE 조건
GROUP BY 그룹기준
HAVING 그룹조건
ORDER BY 정렬기준 [ASC|DESC];
```

실행 순서: `FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY`

### 집계 함수

| 함수 | 의미 |
|------|------|
| `COUNT(*)` | 전체 행 수 |
| `COUNT(컬럼)` | NULL 제외 행 수 |
| `SUM(컬럼)` | 합계 |
| `AVG(컬럼)` | 평균 |
| `MAX(컬럼)` | 최대값 |
| `MIN(컬럼)` | 최소값 |

### HAVING vs WHERE

```sql
-- 과목별 평균이 90 이상인 것만 조회
SELECT 과목, AVG(점수)
FROM 성적
GROUP BY 과목
HAVING AVG(점수) >= 90;   -- 집계 결과에 조건: HAVING 사용
                           -- WHERE는 집계 전 행 필터링
```

### UNION / UNION ALL

```sql
SELECT A FROM T1
UNION          -- 중복 제거 + 정렬
SELECT A FROM T2;

SELECT A FROM T1
UNION ALL      -- 중복 포함
SELECT A FROM T2;
```

### JOIN

```sql
-- INNER JOIN: 두 테이블 모두 값 있는 것만
SELECT * FROM A INNER JOIN B ON A.id = B.id;

-- LEFT JOIN: A 전체 + B에서 매칭되는 것
SELECT * FROM A LEFT JOIN B ON A.id = B.id;
```

### DML (데이터 조작)

```sql
-- 삽입
INSERT INTO 테이블(컬럼1, 컬럼2) VALUES (값1, 값2);

-- 삽입 (조회 결과로)
INSERT INTO 테이블(컬럼1, 컬럼2) SELECT 컬럼1, 컬럼2 FROM 다른테이블 WHERE 조건;

-- 수정
UPDATE 테이블 SET 컬럼 = 값 WHERE 조건;

-- 삭제
DELETE FROM 테이블 WHERE 조건;
```

### DDL (데이터 정의)

```sql
-- 뷰 삭제 (CASCADE: 연관 뷰도 함께 삭제)
DROP VIEW 뷰명 CASCADE;

-- 테이블 구조 변경
ALTER TABLE 테이블 ADD 컬럼 타입;
ALTER TABLE 테이블 DROP COLUMN 컬럼;
```

### 관계 대수 기호

| 연산 | 기호 | 의미 |
|------|------|------|
| select(σ) | σ | 행 선택 (WHERE) |
| project(π) | π | 열 선택 (SELECT) |
| join(⋈) | ⋈ | 테이블 결합 |
| division(÷) | ÷ | 나누기 |

## 4. 소프트웨어 테스트

### 테스트 커버리지 종류 (중요! 자주 출제)

| 커버리지 | 기준 | 설명 |
|---------|------|------|
| **구문(문장) 커버리지** | 모든 구문 1회 이상 실행 | 가장 기본적 |
| **분기(결정) 커버리지** | 모든 분기(YES/NO) 1회 이상 | if의 참/거짓 모두 |
| **조건 커버리지** | 개별 조건식의 T/F 모두 | 복합 조건 각각 |
| **조건/결정 커버리지** | 분기 + 조건 모두 | 위 둘 동시 만족 |
| **변형 조건/결정(MC/DC)** | 각 조건이 결과에 독립적 영향 | 항공/안전 소프트웨어 |
| **다중 조건 커버리지** | 모든 조건 조합 | 가장 강력, 2^n개 케이스 |

```
강도 순서 (약→강):
구문 < 분기 < 조건 < 조건/결정 < 변형조건/결정(MC/DC) < 다중조건
```

### 동등 분할 (Equivalence Partitioning)

- 입력값을 유사한 그룹으로 나눠서 그룹 대표값만 테스트
- "하나의 값이 그 분할 내 모든 값을 대표"
- 경계값 분석과 함께 사용

### 경계값 분석 (Boundary Value Analysis)

- 입력 범위의 경계(최솟값, 최댓값, 그 직전/직후)를 테스트
- 예: 1~100 범위면 → 0, 1, 2, 99, 100, 101 테스트

### 스텁(Stub)과 드라이버(Driver)

| 구분 | 역할 | 사용 시점 |
|------|------|---------|
| **드라이버(Driver)** | 테스트할 모듈을 호출하는 임시 상위 모듈 | **상향식** 통합 테스트 |
| **스텁(Stub)** | 테스트 대상 모듈이 호출하는 임시 하위 모듈 | **하향식** 통합 테스트 |

기억법: **드라이버 = 운전사 (위에서 운전, 상향식)**, **스텁 = 그루터기 (아래에 있음, 하향식)**

### 알파/베타 테스트

| 구분 | 장소 | 참여자 |
|------|------|--------|
| **알파 테스트** | 개발사 내부 | 개발팀 + 선별된 사용자 |
| **베타 테스트** | 사용자 환경 | 실제 사용자 (통제 없음) |

### 블랙박스 vs 화이트박스

| 구분 | 블랙박스 테스트 | 화이트박스 테스트 |
|------|----------------|-----------------|
| 내부 구조 | 모름 | 알고 있음 |
| 기준 | 명세/기능 | 소스코드 구조 |
| 기법 | 동치분할, 경계값, 원인-결과 그래프 | 구문/분기/조건 커버리지 |

## 5. 네트워크 프로토콜

### TCP vs UDP

| 구분 | TCP | UDP |
|------|-----|-----|
| 연결 방식 | 연결형 | 비연결형 |
| 신뢰성 | 높음 (재전송) | 낮음 |
| 속도 | 느림 | 빠름 |
| 순서 보장 | O | X |
| 용도 | HTTP, FTP, 이메일 | DNS, 스트리밍, 게임 |

### 라우팅 프로토콜

| 프로토콜 | 방식 | 특징 |
|---------|------|------|
| **RIP** | 거리 벡터 (Distance Vector) | Hop count 기준, 최대 15홉, IGP |
| **OSPF** | 링크 상태 (Link State) | 최단경로(Dijkstra), 대규모망, IGP |
| **BGP** | 경로 벡터 (Path Vector) | 자율시스템(AS) 간, EGP |

- **IGP** (내부 게이트웨이): AS 내부 라우팅 (RIP, OSPF)
- **EGP** (외부 게이트웨이): AS 간 라우팅 (BGP)

### HDLC 프레임

| 프레임 종류 | 약자 | 역할 |
|------------|------|------|
| **정보 프레임** | I-frame | 실제 데이터 전송 |
| **감독 프레임** | S-frame | 흐름/오류 제어 (ACK, NAK) |
| **비번호 프레임** | U-frame | 링크 설정/해제, 모드 설정 |

HDLC 동작 모드:

| 모드 | 약자 | 특징 |
|------|------|------|
| **정규 응답 모드** | NRM | 종국이 주국의 허가를 받아야 전송 가능. 비균형 구성 |
| **비동기 응답 모드** | ARM | 종국이 주국 허가 없이 전송 시작 가능. 비균형 구성 |
| **비동기 균형 모드** | ABM | 양쪽 모두 복합국(주국+종국 동시). 균형 구성, 점대점 |

- NRM vs ARM: 둘 다 비균형(주국-종국 구조), 차이는 종국이 허가 없이 보낼 수 있냐 없냐
- ABM: 균형 구조 (양쪽이 동등), 가장 많이 쓰임

### ATM (Asynchronous Transfer Mode)

- 셀(Cell) 단위 전송: **고정 길이 53바이트** (헤더 5 + 데이터 48)
- 가상 채널(Virtual Channel) 기반 연결 지향
- 통계적 다중화 사용
- 고속망에 적합 (처리 단순)

### 패킷 교환 방식

| 방식 | 특징 |
|------|------|
| **가상 회선** | 연결형, 경로 미리 설정, 순서 보장 |
| **데이터그램** | 비연결형, 패킷마다 다른 경로, 순서 무관 |

## 6. Python 핵심

### 리스트 슬라이싱

```python
a = [1, 2, 3, 4, 5]
a[1:3]    # [2, 3]    (인덱스 1 이상 3 미만)
a[:3]     # [1, 2, 3] (처음부터 3 미만)
a[2:]     # [3, 4, 5] (인덱스 2부터 끝까지)
a[-1]     # 5         (마지막 원소)
a[::-1]   # [5,4,3,2,1] (역순)
```

문자열도 동일하게 동작:
```python
s = "abdcabcabca"
s[2:2+2]   # "dc"  (인덱스 2부터 길이 2만큼)
```

### split / join

```python
s = "2 3"
a, b = s.split()       # ['2', '3'] → a='2', b='3'
s.split(',')           # 쉼표 기준 분리

lst = ['a', 'b', 'c']
'-'.join(lst)          # 'a-b-c'
```

### set 연산

```python
s = {1, 2, 3}
s.add(4)       # {1, 2, 3, 4}
s.add(2)       # {1, 2, 3, 4}  중복 무시
s.remove(3)    # {1, 2, 4}
s.update({5,6})# {1, 2, 4, 5, 6}  중복 무시

# 집합 연산
A = {1, 2, 3}
B = {2, 3, 4}
A | B   # {1, 2, 3, 4}  합집합
A & B   # {2, 3}        교집합
A - B   # {1}           차집합
```

- set는 **순서 없음** → 인덱스 접근 불가
- set는 **중복 없음**

### 딕셔너리

```python
d = {'name': 'Kim', 'age': 20}
d['name']          # 'Kim'
d.get('age')       # 20
d.get('x', 0)      # 0 (없으면 기본값)
d.keys()           # dict_keys(['name', 'age'])
d.values()         # dict_values(['Kim', 20])
d.items()          # dict_items([('name','Kim'), ('age',20)])
```

### f-string

```python
name = "Kim"
score = 90
f"이름: {name}, 점수: {score}"  # "이름: Kim, 점수: 90"
f"ab{len('abc')}ca"             # "ab3ca"
```

## 7. 보안 공격 / 악성코드

### 악성코드 종류 구분

| 종류 | 특징 |
|------|------|
| **바이러스(Virus)** | 다른 파일에 기생, 사용자 실행 필요, 자기 복제 |
| **웜(Worm)** | 독립 실행, 네트워크로 자동 전파, 숙주 불필요 |
| **트로이목마** | 정상 프로그램으로 위장, 백도어 생성, 자기 복제 없음 |
| **랜섬웨어** | 파일 암호화 후 금전 요구 |
| **루트킷(Rootkit)** | 시스템에 숨어 루트 권한 획득, 탐지 회피 |
| **스파이웨어** | 사용자 정보 몰래 수집 |

### 네트워크 공격

| 공격 | 설명 |
|------|------|
| **DoS** | 서비스 거부 공격 (한 대) |
| **DDoS** | 분산 서비스 거부 (다수 좀비PC) |
| **스머프(Smurf)** | 위조 IP로 브로드캐스트 ICMP, 대상에 집중 공격 |
| **SYN Flooding** | TCP 3-way handshake의 SYN만 보내고 ACK 안 함 |
| **세션 하이재킹** | 인증된 세션 탈취 |
| **APT** | 지능형 지속 위협, 오랜 기간 잠복 후 공격 |

### 악성코드 추가

| 종류 | 특징 |
|------|------|
| **애드웨어(Adware)** | 광고를 강제로 표시, 사용자 동의 없이 설치 |
| **백도어(Backdoor)** | 인증 우회 비밀 통로 생성, 원격 제어 허용 |
| **키로거(Keylogger)** | 키보드 입력 기록 → 비밀번호/개인정보 탈취 |
| **봇(Bot) / 봇넷** | 원격 제어되는 좀비PC, 다수 모이면 봇넷(DDoS 등에 활용) |
| **드로퍼(Dropper)** | 악성코드를 시스템에 심는 역할만 수행 |
| **익스플로잇(Exploit)** | 소프트웨어 취약점을 이용한 공격 코드 |

### 네트워크 공격 추가

| 공격 | 설명 |
|------|------|
| **IP 스푸핑(Spoofing)** | 출발지 IP를 위조하여 신뢰된 호스트인 척 |
| **스니핑(Sniffing)** | 네트워크 패킷을 엿듣는 도청 공격 |
| **포트 스캐닝** | 열려 있는 포트를 탐색해 공격 대상 탐색 |
| **Land Attack** | 출발지 IP = 목적지 IP로 위조해 자기 자신에게 패킷 전송 |
| **Teardrop** | IP 단편화(Fragment) 패킷 재조합 오류 유발 |
| **Ping of Death** | 규격 초과 크기의 ICMP 패킷 전송 → 시스템 충돌 |

### 사회공학적 공격

| 공격 | 설명 |
|------|------|
| **피싱(Phishing)** | 가짜 사이트/이메일로 개인정보 탈취 |
| **파밍(Pharming)** | DNS 변조로 정상 URL 입력해도 가짜 사이트로 이동 |
| **스피어 피싱** | 특정 개인/조직을 타겟으로 한 정밀 피싱 |
| **스미싱(Smishing)** | SMS로 악성 링크 전송 |
| **보이스 피싱** | 전화를 이용한 사기 |

### 웹 공격

| 공격 | 설명 | 예방 |
|------|------|------|
| **SQL Injection** | SQL 쿼리에 악의적 코드 삽입 | 입력값 검증, PreparedStatement |

## 9. DB 릴레이션 이론

### 기본 용어

| 용어 | 의미 | 비유 |
|------|------|------|
| **릴레이션(Relation)** | 테이블 | 표 전체 |
| **튜플(Tuple)** | 행(Row) | 한 줄의 데이터 |
| **속성(Attribute)** | 열(Column) | 컬럼 |
| **도메인(Domain)** | 속성이 가질 수 있는 값의 범위 | 성별 → {남, 여} |
| **Degree(차수)** | 속성(열)의 수 | 컬럼 개수 |
| **Cardinality(기수)** | 튜플(행)의 수 | 행 개수 |
| **스키마** | 릴레이션 구조 정의 | 테이블 설계도 |
| **인스턴스(외연)** | 실제 저장된 데이터 | 현재 데이터 내용 |

```
예시 테이블:
학번 | 이름 | 학과 | 학년 | 성별    ← Degree = 5 (열 5개)
001  | 홍길동 | 컴퓨터 | 1 | 남     ← 튜플 1
002  | 임꺽정 | 전자 | 2 | 남      ← 튜플 2
003  | 유관순 | 컴퓨터 | 3 | 여     ← 튜플 3
                                    ← Cardinality = 3 (행 3개)
```

## 10. DB 정규화

### 정규화란?

데이터 **중복을 제거**하고 **이상현상(Anomaly)을 방지**하기 위해 테이블을 분해하는 과정

### 이상 현상 (Anomaly)

| 이상현상 | 설명 |
|---------|------|
| **삽입 이상** | 데이터 삽입 시 원하지 않는 값도 같이 삽입해야 함 |
| **삭제 이상** | 데이터 삭제 시 필요한 다른 정보도 함께 삭제 |
| **갱신 이상** | 중복 데이터 수정 시 일부만 수정되어 불일치 발생 |

### 정규형 단계

```
비정규 → 1NF → 2NF → 3NF → BCNF → 4NF → 5NF
```

| 정규형 | 조건 |
|--------|------|
| **1NF** | 모든 속성이 원자값 (더 이상 나눌 수 없는 단일 값) |
| **2NF** | 1NF + 부분 함수 종속 제거 (기본키 전체에 종속) |
| **3NF** | 2NF + 이행 함수 종속 제거 (A→B→C에서 A→C 제거) |
| **BCNF** | 3NF + 모든 결정자가 후보키 |

### 함수 종속

- `A → B`: A 값이 결정되면 B 값이 유일하게 결정됨
- **부분 종속**: 기본키 일부에만 종속 (복합키인 경우)
- **이행 종속**: A→B, B→C 일 때 A→C

## 11. DB 트랜잭션

### ACID 성질

| 성질 | 의미 |
|------|------|
| **원자성(Atomicity)** | 트랜잭션 전부 실행되거나 전부 취소 (All or Nothing) |
| **일관성(Consistency)** | 트랜잭션 전후 데이터 일관성 유지 |
| **격리성(Isolation)** | 동시 실행 트랜잭션들이 서로 영향 안 줌 |
| **지속성(Durability)** | 완료된 트랜잭션 결과는 영구 저장 |

### Commit / Rollback

| 명령 | 의미 |
|------|------|
| **Commit** | 트랜잭션 결과를 DB에 영구 반영 |
| **Rollback** | 트랜잭션 취소, 이전 상태로 복구 |

### Redo / Undo

| 명령 | 의미 | 사용 시점 |
|------|------|---------|
| **Redo** | 트랜잭션 재실행 | 장애 후 완료된 트랜잭션 복구 |
| **Undo** | 트랜잭션 취소/되돌리기 | 완료 안 된 트랜잭션 제거 |

## 12. DB 키 / 무결성

### 키 종류

| 키 | 설명 |
|----|------|
| **슈퍼키** | 유일성 O, 최소성 X (컬럼 여러 개 조합) |
| **후보키** | 유일성 O + 최소성 O |
| **기본키(PK)** | 후보키 중 선택, NULL 불가, 중복 불가 |
| **대체키** | 기본키로 선택 안 된 나머지 후보키 |
| **외래키(FK)** | 다른 테이블의 기본키를 참조 |

```
유일성: 모든 튜플에서 유일하게 식별 가능
최소성: 필요 최소한의 속성으로만 구성
```

### 무결성 종류

| 무결성 | 설명 |
|--------|------|
| **개체 무결성** | 기본키는 NULL 불가, 중복 불가 |
| **참조 무결성** | 외래키 값은 참조 테이블 기본키에 존재해야 함 |
| **도메인 무결성** | 속성값은 도메인 범위 안에 있어야 함 |
| **사용자 정의 무결성** | 업무 규칙에 따른 제약 |

## 13. 결합도 / 응집도

> 상세 내용은 `결합도응집도.md` 참조

### 결합도 (낮을수록 좋음)

```
약함(좋음) ←――――――――――――――――→ 강함(나쁨)
자료 - 스탬프 - 제어 - 외부 - 공통 - 내용
```

기억법: **자스제외공내**

| 결합도 | 설명 |
|--------|------|
| **자료(Data)** | 단순 데이터만 주고받음 (가장 좋음) |
| **스탬프(Stamp)** | 자료구조 공유 |
| **제어(Control)** | 제어 신호 전달로 다른 모듈 흐름 제어 |
| **외부(External)** | 외부 변수 공유 |
| **공통(Common)** | 전역 변수 공유 |
| **내용(Content)** | 다른 모듈 내부 직접 참조 (가장 나쁨) |

### 응집도 (높을수록 좋음)

```
강함(좋음) ←――――――――――――――――→ 약함(나쁨)
기능 - 순차 - 교환 - 절차 - 시간 - 논리 - 우연
```

기억법: **기순교절시논우**

| 응집도 | 설명 |
|--------|------|
| **기능적** | 하나의 기능만 수행 (가장 좋음) |
| **순차적** | 앞 기능 출력이 다음 기능 입력 |
| **교환적** | 같은 데이터로 다른 기능 수행 |
| **절차적** | 순서대로 실행되는 기능들 |
| **시간적** | 같은 시간에 실행되는 기능들 |
| **논리적** | 유사한 성격의 기능들 묶음 |
| **우연적** | 아무 관계 없는 기능들 묶음 (가장 나쁨) |

|------|------|
| **구조 다이어그램** | 클래스, 객체, 컴포넌트, 배치, 패키지, 복합구조 |
| **행위 다이어그램** | 유스케이스, 시퀀스, 활동, 상태, 통신, 타이밍, 상호작용 |

### 클래스 다이어그램 관계

| 관계 | 기호 | 의미 |
|------|------|------|
| **연관(Association)** | ─── | 서로 관련 있음 |
| **의존(Dependency)** | - - → | 한쪽이 다른 쪽을 사용 |
| **일반화(Generalization)** | ──▷ | 상속 (is-a) |
| **실체화(Realization)** | - -▷ | 인터페이스 구현 |
| **집합(Aggregation)** | ──◇ | 부분-전체 (독립) |
| **복합(Composition)** | ──◆ | 부분-전체 (종속) |

### 패키지 다이어그램

```
[ordering] ────────────────────→ [pricing]   (의존)
[ordering] ──<<import>>──────→ [products]  (임포트)
```

- `<<import>>`: 패키지의 요소를 가져와서 사용
- 화살표 방향 = 의존 방향

## 15. 암호화 알고리즘

### 대칭키 vs 비대칭키

| 구분 | 대칭키 | 비대칭키 |
|------|--------|---------|
| 키 개수 | 1개 (암복호화 같은 키) | 2개 (공개키 + 개인키) |
| 속도 | 빠름 | 느림 |
| 키 관리 | 어려움 (N명이면 N(N-1)/2개 필요) | 쉬움 |
| 알고리즘 | DES, **AES**, ARIA, SEED | **RSA**, ECC, ElGamal |

### 주요 알고리즘

| 알고리즘 | 종류 | 특징 |
|---------|------|------|
| **AES** | 대칭키 | DES 대체, 128/192/256비트 키, 블록 128비트 |
| **DES** | 대칭키 | 64비트 키 (실질 56비트), 구식 |
| **ARIA** | 대칭키 | **국산** 암호화, 128/192/256비트 키, 블록 128비트, 국정원 개발 |
| **SEED** | 대칭키 | **국산** 암호화, 128비트 키, 블록 128비트, KISA(한국인터넷진흥원) 개발 |
| **RSA** | 비대칭키 | 큰 수 소인수분해 어려움 이용 |
| **ECC** | 비대칭키 | 타원 곡선, RSA보다 짧은 키로 동등 안전 |
| **SHA** | 해시 | 단방향, 무결성 검증 |
| **MD5** | 해시 | 128비트, 취약점 발견됨 |

### 오류 검출/정정 코드

| 코드 | 역할 |
|------|------|
| **Hamming Code** | 1비트 오류 **정정** 가능 |
| **FEC (전진 오류 수정)** | 수신측이 자체적으로 오류 정정 (재전송 없음) |
| **BEC (후진 오류 수정)** | 오류 검출 후 재전송 요청 |
| **패리티 비트** | 오류 **검출** (홀수/짝수 패리티) |
| **CRC** | 다항식으로 체크값 계산, 버스트 오류 검출 |

## 16. 클라우드 / NAT / VPN

### 클라우드 서비스 모델

| 모델 | 제공 범위 | 기업이 관리하는 것 |
|------|---------|----------------|
| **IaaS** | 가상화·서버·스토리지·네트워크 | OS·미들웨어·앱·데이터 |
| **PaaS** | IaaS + OS·미들웨어·런타임 | 앱·데이터 |
| **SaaS** | 전부 다 제공 | 없음 (사용만) |

```
전통적 IT: 기업이 전부 관리
IaaS: 인프라만 제공받고 나머지는 기업이 관리
PaaS: 플랫폼까지 제공받고 앱만 기업이 관리
SaaS: 소프트웨어 자체를 서비스로 사용 (ex. Gmail)
```

### NAT (Network Address Translation)

- 사설 IP ↔ 공인 IP 변환
- 라우터에서 내부 IP 주소와 포트를 공인 IP로 재기록
- 인터넷 공유, IP 주소 부족 해결

### VPN (Virtual Private Network)

- 공용 인터넷을 통해 **사설 네트워크** 연결
- 터널링(Tunneling)으로 암호화된 통신

### IPSec

- **네트워크 계층(3계층)**에서 IP 패킷 암호화/인증
- **AH** (Authentication Header): 인증만
- **ESP** (Encapsulating Security Payload): 암호화 + 인증
- VPN 구현에 사용

### L2TP

- **데이터링크 계층(2계층)** VPN 프로토콜
- 주로 IPSec과 함께 사용

## 17. 스케줄링

### 스케줄링 종류

| 알고리즘 | 방식 | 특징 |
|---------|------|------|
| **FCFS** | 선점 불가 | 도착 순서대로 처리, 간단 |
| **SJF** | 선점 불가 | 실행 시간 짧은 것 먼저, 기아 현상 |
| **SRT** | 선점 가능 | 남은 시간 가장 짧은 것 먼저 (SJF 선점 버전) |
| **Round Robin** | 선점 | 시간 할당량(Quantum)씩 순환, 공평 |
| **HRN** | 선점 불가 | 우선순위 = (대기시간+서비스시간)/서비스시간 |

### SRT 계산 예시

```
프로세스  도착시간  서비스시간
A         0        8
B         1        4
C         2        9
D         3        5

타임라인:
0-1: A 실행 (남은 시간: A=7)
1-2: B 실행 (남은 시간: B=3, B<A)
2-3: B 실행 (남은 시간: B=2, B<D=5)
3-5: B 실행 완료 (B=0)
5-10: D 실행 완료 (D<A남은7)
10-18: A 실행 완료
18-27: C 실행 완료

대기시간: A=10-1=9? → 계산은 문제마다 타임라인 직접 추적할 것
```

## 18. 접근 통제

### 서버 접근 통제 유형

| 유형 | 영어 약자 | 특징 |
|------|---------|------|
| **임의적 접근 통제** | **DAC** (Discretionary AC) | 신분 기반, 자원 소유자가 권한 결정 |
| **강제적 접근 통제** | **MAC** (Mandatory AC) | 규칙 기반, 허용 등급·권한 수준으로 결정 (보안 등급) |
| **역할 기반 접근 통제** | **RBAC** (Role-Based AC) | 역할(Role) 기반, 중앙 관리자가 통제 |

```
DAC: 파일 소유자가 읽기/쓰기 권한 직접 부여 (리눅스 chmod)
MAC: 군사 등급처럼 TOP SECRET / SECRET / CONFIDENTIAL 등급 체계
RBAC: 팀장 역할 = 이런 권한, 직원 역할 = 저런 권한
```

### 리눅스 파일 권한 (chmod)

```
chmod 751 test.txt

7 = 111 = 읽기(4) + 쓰기(2) + 실행(1) = 소유자
5 = 101 = 읽기(4) + 실행(1)           = 그룹
1 = 001 = 실행(1)                      = 기타

r=4, w=2, x=1
```
