### Q02 해설 — 비트 연산자 우선순위
```
우선순위: >> > & > ^ > |  (산술 연산자처럼 높을수록 먼저)

x = 15 = 1111(2)
y =  6 = 0110(2)

─────────────────────────────────────────
① x & y >> 1
─────────────────────────────────────────
  >> 가 & 보다 우선 → x & (y >> 1)
  y >> 1 = 0110 >> 1 = 0011 = 3
  x & 3  = 1111 & 0011 = 0011 = 3
  → 출력: 3

─────────────────────────────────────────
② x | y ^ 2
─────────────────────────────────────────
  ^ 가 | 보다 우선 → x | (y ^ 2)
  y ^ 2 = 0110 ^ 0010 = 0100 = 4
  x | 4 = 1111 | 0100 = 1111 = 15
  → 출력: 15

─────────────────────────────────────────
③ x >> 2 & y
─────────────────────────────────────────
  >> 가 & 보다 우선 → (x >> 2) & y
  x >> 2 = 1111 >> 2 = 0011 = 3
  3 & y  = 0011 & 0110 = 0010 = 2
  → 출력: 2
```

### Q04 해설 — 구조체 포인터 + 문자열 포인터 연산
```
arr[0] = {2, "KOREA"}
arr[1] = {3, "JAPAN"}
arr[2] = {1, "CHINA"}
p = &arr[0]

─────────────────────────────────────────
① printf("%s\n", p->s + p->n)
─────────────────────────────────────────
  p->s = "KOREA" (= 'K'의 주소)
  p->n = 2

  문자열 포인터 + 정수 → 그 위치부터의 주소
  "KOREA" + 2 → 인덱스 2인 'R'의 주소
     K O R E A
     0 1 2 3 4
           ↑ 여기서부터 %s 출력

  → "REA"

─────────────────────────────────────────
② printf("%c\n", *(arr[2].s + arr[1].n - 1))
─────────────────────────────────────────
  arr[2].s = "CHINA" (= 'C'의 주소)
  arr[1].n = 3

  "CHINA" + 3 - 1 = "CHINA" + 2 → 인덱스 2인 'I'의 주소
     C H I N A
     0 1 2 3 4
         ↑

  * 로 역참조 → 문자 하나 꺼냄 → 'I'
  %c 출력 → I
```

### Q07 해설 — 딕셔너리 + 다중 정렬 키
```
words = ["apple","banana","apple","cherry","apple","banana","banana"]

─────────────────────────────────────────
① count 딕셔너리 구성
─────────────────────────────────────────
  apple  등장: 3회
  banana 등장: 3회
  cherry 등장: 1회
  count = {'apple':3, 'banana':3, 'cherry':1}

─────────────────────────────────────────
② sorted(count.items(), key=lambda x: (-x[1], x[0]))
─────────────────────────────────────────
  x = (단어, 빈도) 튜플
  정렬 키 = (-빈도, 단어)

    (-3, 'apple')  ← -3 < -1, 그리고 'apple' < 'banana'
    (-3, 'banana')
    (-1, 'cherry')

─────────────────────────────────────────
③ f"{k}:{v}" end=" " 출력
─────────────────────────────────────────
  apple:3 banana:3 cherry:1 (마지막도 공백 포함)

### Q14 해설 — 정규화 단계 판별 (3NF vs BCNF)
```
릴레이션: 수강(학번, 과목코드, 담당교수, 성적)
후보키:  (학번, 과목코드)
주어진 함수 종속:
  ① (학번, 과목코드) → 담당교수
  ② (학번, 과목코드) → 성적
  ③ 담당교수 → 과목코드

─────────────────────────────────────────
2NF 확인 — 부분 함수 종속이 있는가?
─────────────────────────────────────────
  부분 FD = 복합키의 일부만으로 비키 속성 결정
  주어진 FD 중 '과목코드만으로 담당교수 결정'은 없음
  → 부분 FD 없음 → 2NF 만족 ✓

─────────────────────────────────────────
3NF 확인 — 비키→비키 이행 종속이 있는가?
─────────────────────────────────────────
  ③ 담당교수 → 과목코드
  과목코드는 후보키의 일부 (= 주요 속성, prime attribute)
  3NF 위반 조건: 비키 속성이 비키 속성을 결정
  → 과목코드는 비키가 아닌 주요 속성 → 3NF 위반 아님
  → 3NF 만족 ✓

─────────────────────────────────────────
BCNF 확인 — 모든 결정자가 후보키인가?
─────────────────────────────────────────
  ③ 담당교수 → 과목코드
  담당교수는 후보키가 아님 (담당교수만으로 튜플 식별 불가)
  → BCNF 위반 ✗

최고 정규형 = 3NF
```

### Q17 해설 — SRT 스케줄링 간트 차트
```
| 프로세스 | 도착 | 처리시간 |
|---------|------|---------|
| P1      |  0   |    8    |
| P2      |  2   |    3    |
| P3      |  5   |    4    |
| P4      |  7   |    2    |

SRT: 현재 실행 중인 프로세스보다 남은 시간이 짧은 프로세스 도착 시 선점

t=0: P1 도착 → P1 실행  (P1 잔여=8)
t=2: P2 도착 (잔여=3) vs P1 잔여=6  →  3 < 6  →  P2가 P1 선점
t=5: P2 완료 (2~5, 3단위 실행)
     대기 중: P1(잔여=6), P3(방금 도착, 잔여=4)
     4 < 6  →  P3 실행
t=7: P4 도착 (잔여=2) vs P3 잔여=2  →  동점 → 현재 프로세스 유지 → P3 계속
t=9: P3 완료 (5~9, 4단위 실행)
     대기 중: P1(잔여=6), P4(잔여=2)
