# 정보처리기사 실기 — 이론 예상문제 해설

---

## Part 1. 단답형 해설

### [1장] 요구사항 확인

**Q01.** 나선형(Spiral) 모형
> 계획 → 위험 분석 → 개발 및 검증 → 고객 평가의 4단계를 반복. **위험 최소화**가 핵심 키워드. 보헴(Boehm)이 제안.

**Q02.** 테스트 주도 개발(TDD, Test Driven Development)
> XP의 실천 방법. **테스트 먼저 작성 → 코드 작성** 순서. 코드가 테스트를 통과하면 완성.

**Q03.** 조직형(Organic)
> COCOMO 3가지: 조직형(5만 라인 이하) / 반분리형(30만 라인 이하) / 내장형(30만 라인 이상)

**Q04.** Putnam 모형
> Rayleigh-Norden 곡선 이용. 수명 주기 전 과정의 인력 분포를 가정. SLIM 도구 사용.

**Q05.** CMMI(Capability Maturity Model Integration)
> 5단계: 초기(Initial) → 관리(Managed) → 정의(Defined) → 정량적 관리(Quantitatively Managed) → 최적화(Optimizing)

**Q06.** SPICE(ISO/IEC 15504)
> 소프트웨어 프로세스 **평가와 개선** 지원. ISO/IEC 15504가 공식 명칭.

### [2장] 데이터 입출력 구현

**Q07.** 외부 스키마
> 사용자/응용 프로그래머 관점. **서브 스키마(Sub Schema)**라고도 함. 여러 개 존재 가능.

**Q08.** 내부 스키마
> **물리적 저장 장치** 관점. 실제 저장 형식, 접근 경로 등 정의. 1개만 존재.

**Q09.** 타원(○)
> E-R 다이어그램 기호: 사각형=개체, 타원=속성, 마름모=관계, 선=링크

**Q10.** 카디널리티(Cardinality)
> 튜플(행)의 수. 카디널리티 ↑ = 데이터 많음. 기수라고도 함.

**Q11.** 디그리(Degree, 차수)
> 속성(열)의 수. 디그리 = 애트리뷰트 수.

**Q12.** 후보키(Candidate Key)
> **유일성**(모든 튜플 유일 식별) + **최소성**(최소 속성으로 구성) 둘 다 만족.

**Q13.** 대체키(Alternate Key)
> 후보키 중 기본키로 선택되지 못한 나머지 키.

**Q14.** 개체 무결성(Entity Integrity)
> 기본키는 NULL 불가, 중복 불가. (참조 무결성과 구분: 외래키가 참조하는 테이블의 기본키여야 함)

**Q15.** Select(셀렉트, σ)
> 행(튜플) 추출. σ 조건(릴레이션). 수평 연산.

**Q16.** Project(프로젝트, π)
> 열(속성) 추출. π 속성목록(릴레이션). 수직 연산.

**Q17.** 삭제 이상(Deletion Anomaly)
> 이상(Anomaly) 3가지: 삽입 이상 / **삭제 이상** / 갱신 이상. 삭제 시 불필요한 정보도 같이 삭제.

**Q18.** 함수적 종속(Functional Dependency)
> X → Y: X가 Y를 결정함(X가 Y에 함수적으로 종속).

**Q19.** 이행적 함수적 종속(Transitive Functional Dependency)
> X→Y, Y→Z → X→Z. 3NF에서 제거해야 하는 종속 관계.

**Q20.** 제 1정규형(1NF)
> 모든 속성값이 **원자값(더 이상 분해 불가)**이어야 함.

**Q21.** 제 2정규형(2NF)
> 1NF + **완전 함수적 종속**(기본키 전체에 종속, 부분 종속 제거).

**Q22.** 제 3정규형(3NF)
> 2NF + **이행적 함수적 종속 제거**(기본키가 아닌 속성 간 종속 제거).

**Q23.** 반정규화(Denormalization)
> 성능 향상을 위해 정규화된 테이블을 의도적으로 합치거나 중복 허용. 조회 성능↑, 데이터 일관성↓.

**Q24.** 데이터 사전(Data Dictionary)
> 시스템 카탈로그. DB 자체에 대한 정보를 담는 메타데이터 저장소. 사용자가 직접 수정 불가.

**Q25.** 원자성(Atomicity)
> All or Nothing. COMMIT(모두 반영) 또는 ROLLBACK(전혀 반영 안 함).

**Q26.** 독립성(Isolation) / 격리성
> 트랜잭션 실행 중 다른 트랜잭션이 끼어들 수 없음. 직렬화(Serializability)와 관련.

**Q27.** 뷰(View)
> 하나 이상의 테이블로부터 유도된 **가상 테이블**. 실제 데이터는 없고 논리적으로만 존재.

**Q28.** RPO(Recovery Point Objective)
> 목표 복구 시점. **어느 시점까지** 복원할 수 있는지. (RTO: 목표 복구 시간 — 얼마나 빨리 복구하는지)

**Q29.** SAN(Storage Area Network)
> 서버-저장장치 간 **전용 네트워크** 구성. (NAS: 네트워크에 연결된 파일 서버 방식)

**Q30.** 배열, 스택, 큐, 연결 리스트
> 선형: 배열, 스택, 큐, 연결 리스트 / 비선형: 트리, 그래프

**Q31.** Preorder(전위) 운행법
> Root → Left → Right

**Q32.** Inorder(중위) 운행법
> Left → Root → Right

**Q33.** Postorder(후위) 운행법
> Left → Right → Root

**Q34.** 선택 정렬(Selection Sort)
> 최솟값을 찾아 앞으로 이동. O(n²). 교환 횟수 최소.

**Q35.** 버블 정렬(Bubble Sort)
> 인접한 두 원소 비교·교환 반복. O(n²). 구현 가장 단순.

**Q36.** 퀵 정렬(Quick Sort)
> 피벗 기준으로 분할. 평균 O(nlog₂n), 최악 O(n²). 실제로 가장 빠른 정렬.

### [3장] 통합 구현

**Q37.** SOAP(Simple Object Access Protocol)
> HTTP 기반 XML 메시지 교환 프로토콜. 웹 서비스 3요소: **SOAP**(통신) / **WSDL**(명세) / **UDDI**(검색)

**Q38.** WSDL(Web Services Description Language)
> 웹 서비스의 기능·위치·프로토콜을 XML로 기술. UDDI에 등록되어 검색됨.

### [4장] 서버 프로그램 구현

**Q39.** 모듈화(Modularity)
> 결합도 최소화 + 응집도 최대화. 독립적이고 재사용 가능한 모듈로 분리.

**Q40.** 정보 은닉(Information Hiding)
> 모듈 내부 정보를 외부에서 접근 못하게 숨김. 캡슐화(Encapsulation)와 유사 개념.

**Q41.** 협약(Contract)에 의한 설계
> 선행 조건(Precondition) / 결과 조건(Postcondition) / 불변 조건(Invariant) 명세.

**Q42.** 럼바우(Rumbaugh) 방법
> OMT(Object Modeling Technique). 객체 모델 / 동적 모델 / 기능 모델.

**Q43.** 개방-폐쇄 원칙(OCP, Open-Closed Principle)
> 확장에는 열려 있고(Open), 수정에는 닫혀 있어야(Closed) 함.

**Q44.** 리스코프 치환 원칙(LSP, Liskov Substitution Principle)
> 자식 클래스는 부모 클래스를 대체할 수 있어야 함.

**Q45.** 결합도(Coupling)
> 모듈 간 의존 정도. **낮을수록 좋음**. (강 → 약: 내용 > 공통 > 외부 > 제어 > 스탬프 > 자료)

**Q46.** 응집도(Cohesion)
> 모듈 내 요소들의 관련 정도. **높을수록 좋음**. (강 → 약: 기능 > 순차 > 교환 > 절차 > 시간 > 논리 > 우연)

**Q47.** 팬인(Fan-In)
> 어떤 모듈을 **호출하는** 모듈의 수. 팬인 높음 = 공유도 높음 = 중요도 높음.

**Q48.** 팬아웃(Fan-Out)
> 어떤 모듈이 **호출하는** 모듈의 수. 팬아웃 높음 = 복잡도 높음.

**Q49.** 우연적 응집도(Coincidental Cohesion)
> 응집도 가장 낮음. 서로 관련 없는 기능이 우연히 한 모듈에 모임.

**Q50.** 기능적 응집도(Functional Cohesion)
> 응집도 가장 높음. 모듈 내 모든 요소가 단 하나의 기능만 수행.

**Q51.** GOF(Gang of Four)
> Gamma, Helm, Johnson, Vlissides 4명. 디자인 패턴 23가지를 생성/구조/행위로 분류.

**Q52.** 싱글톤(Singleton)
> 생성 패턴. 인스턴스가 단 하나. static으로 유일한 객체 보장.

**Q53.** 어댑터(Adapter)
> 구조 패턴. 호환되지 않는 인터페이스를 변환. 220V→110V 변환기에 비유.

**Q54.** 커맨드(Command)
> 행위 패턴. 요청을 객체로 캡슐화. 실행 취소(Undo) 구현 가능.

**Q55.** 파이프-필터 패턴(Pipe-Filter Pattern)
> 아키텍처 패턴. 데이터 → 필터1 → 파이프 → 필터2 → ... UNIX 파이프(|)가 대표 예.

**Q56.** 연상 코드(Mnemonic Code)
> 명칭이나 약호와 관련된 코드. TV-40(40인치 TV). 기억하기 쉬움.

### [11장] 응용 SW 기초 기술 활용

**Q57.** 운영체제(OS; Operating System)
> 하드웨어와 사용자 사이의 중재자. 프로세스/메모리/파일/입출력 자원 관리.

**Q58.** UNIX
> 1969년 AT&T 벨 연구소. 멀티태스킹, 다중 사용자, 트리 구조 파일 시스템.

**Q59.** 커널(Kernel)
> UNIX의 핵심. 하드웨어 보호 + 프로그램-하드웨어 인터페이스. 메모리 상주.

**Q60.** 페이징(Paging) 기법
> 동일 크기 블록(페이지)으로 분할. 내부 단편화 발생. 외부 단편화 없음.
> (세그멘테이션: 가변 크기, 외부 단편화 발생)

**Q61.** FIFO(First In First Out)
> 가장 먼저 들어온 페이지 교체. 구현 단순. Belady's Anomaly 발생 가능.

**Q62.** LRU(Least Recently Used)
> 가장 오랫동안 사용하지 않은 페이지 교체. 가장 많이 사용되는 기법.

**Q63.** LFU(Least Frequently Used)
> 사용 빈도 가장 적은 페이지 교체. 활발히 사용되는 페이지는 남아있음.

**Q64.** 스래싱(Thrashing)
> 페이지 교체 시간 > 프로세스 처리 시간. 다중 프로그래밍 정도가 너무 높을 때 발생. 워킹 셋으로 예방.

**Q65.** Locality(지역성)
> 일부 페이지만 집중 참조하는 성질. **시간 지역성**(최근 참조 재참조) + **공간 지역성**(인근 주소 참조).

**Q66.** 워킹 셋(Working Set)
> 일정 시간 동안 자주 참조되는 페이지 집합. 주기억장치에 상주시켜 스래싱 예방.

**Q67.** Dispatch(디스패치)
> 준비 상태 → 실행 상태 전이. CPU 스케줄러가 수행.

**Q68.** Spooling(스풀링)
> 느린 입출력 장치 처리 보완. 디스크에 임시 저장 후 한꺼번에 처리. 프린터 큐가 대표 예.

**Q69.** 스레드(Thread)
> 프로세스 내의 작업 단위. 경량 프로세스. 같은 프로세스의 스레드끼리 메모리 공유.

**Q70.** SJF(Shortest Job First)
> 실행 시간 가장 짧은 프로세스 먼저. 비선점형. 평균 대기 시간 최소.
> (SRT: 선점형 SJF — 남은 시간 기준으로 선점 가능)

**Q71.** HRN(Highest Response-ratio Next)
> 우선순위 = (대기 시간 + 서비스 시간) / 서비스 시간. SJF의 기아(Starvation) 문제 보완.

**Q72.** RR(Round Robin)
> 시간 할당량(Time Quantum)만큼 순환 실행. 시분할 시스템. 시간 할당량↓ = 문맥교환↑.

**Q73.** NAT(Network Address Translation)
> 사설 IP ↔ 공인 IP 변환. IPv4 주소 부족 문제 해결책 중 하나.

**Q74.** IPv6
> 128비트. 16진수 8그룹, 콜론(:) 구분. IPv4 주소 고갈 해결. IPSec 기본 내장.

**Q75.** 시간(Timing)
> 프로토콜 3요소: **구문(Syntax)**(형식/구조) / **의미(Semantics)**(제어 정보 의미) / **시간(Timing)**(속도·순서 제어)

**Q76.** 전송 계층(Transport Layer, 4계층)
> End-to-End 신뢰성 전송. TCP(연결형)/UDP(비연결형). 포트 번호 사용.

**Q77.** UDP(User Datagram Protocol)
> 비연결형. 빠르지만 신뢰성 낮음. 스트리밍, DNS, DHCP 등에 사용.

**Q78.** ARP(Address Resolution Protocol)
> IP 주소 → MAC 주소 변환. (RARP: MAC 주소 → IP 주소)

**Q79.** RIP(Routing Information Protocol)
> 거리 벡터(Distance Vector) 방식. Bellman-Ford 알고리즘. 최대 15홉 제한. IGP.

**Q80.** OSPF(Open Shortest Path First)
> 링크 상태(Link State) 방식. Dijkstra 알고리즘. 홉 제한 없음. RIP보다 빠른 수렴. IGP.

**Q81.** 슬라이딩 윈도우(Sliding Window)
> ACK 없이 윈도우 크기만큼 연속 전송. 전송 효율↑. 흐름 제어 기법.

**Q82.** SSO(Single Sign On)
> 한 번 로그인으로 여러 서비스 이용. 인증 정보를 중앙에서 관리.

**Q83.** RAID 1
> 미러링(Mirroring). 동일 데이터를 2개 디스크에 저장. 안전성↑, 용량 효율 50%.

**Q84.** 상호 배제, 점유와 대기, 비선점, 환형 대기
> 교착상태 4조건. 이 중 하나라도 제거하면 교착상태 예방 가능(예방 기법).

**Q85.** 회피 기법(Avoidance)
> 은행원 알고리즘(Banker's Algorithm). 자원 할당 전 안전 상태 여부 확인.

**Q86.** SCM(Software Configuration Management, 형상 관리)
> 소스코드 변경 이력 관리. Git, SVN, CVS 등.

**Q87.** DRM(Digital Rights Management)
> 디지털 저작권 관리. 구성: 클리어링 하우스 / 콘텐츠 제공자 / 패키저 / 콘텐츠 분배자 / DRM 컨트롤러

**Q88.** 빌드 자동화 도구
> Jenkins(CI 서버), Gradle(안드로이드), Maven, Ant, Make 등. 빌드+테스트+배포 자동화.

**Q89.** REDO
> 트랜잭션 start + commit 기록 있음 → 다시 실행(재작업). 완료된 작업 복원.

**Q90.** UNDO
> 트랜잭션 start 기록만 있고 commit 없음 → 취소(롤백). 미완료 작업 원상복구.

### [12장] 제품 소프트웨어 패키징

**Q91.** 클리어링 하우스(Clearing House)
> DRM 구성 요소. 라이선스 발급, 사용 권한 관리, 키 관리, 결제 처리.

**Q92.** 패키저(Packager)
> DRM 구성 요소. 콘텐츠를 메타데이터와 묶어 암호화하는 프로그램.

**Q93.** 형상 식별
> SCM 활동 4가지: **형상 식별** / 형상 통제 / 형상 감사 / 형상 기록(상태 보고). 이름과 번호 부여.

**Q94.** 체크인(Check-In)
> 수정 완료 후 저장소에 새 버전으로 갱신. (체크아웃: 저장소에서 파일 꺼내 수정)

**Q95.** Gradle
> Groovy 기반. 안드로이드 기본 빌드 도구. 빌드 스크립트를 코드로 작성.

---

### [5장] 인터페이스 구현

**Q96.** 인스펙션(Inspection)
> 요구사항 명세서 작성자 **제외**한 전문가들이 검토. 동료 검토(Peer Review)의 한 종류.

**Q97.** TP-Monitor(트랜잭션 처리 모니터)
> 항공기 예약, 은행 등 대용량 트랜잭션 처리. 사용자 수 증가에도 빠른 응답 유지.

**Q98.** Hub & Spoke
> EAI 방식. 중앙 허브를 통해 모든 연동. 확장/유지보수 용이. 허브 장애 시 전체 영향.

**Q99.** IPsec(IP Security)
> 네트워크 계층(3계층). AH(인증)+ESP(암호화+인증). VPN 구현에 사용.

**Q100.** AJAX(Asynchronous JavaScript and XML)
> 비동기 통신. 전체 페이지 갱신 없이 **일부만 업데이트**. XMLHttpRequest 객체 사용.

**Q101.** NTAF
> NHN Test Automation Framework. FitNesse(협업) + STAF(재사용·확장성) 통합.

**Q102.** Tripwire
> 파일 변경 감지 도구. 해시값 비교로 무결성 검사. "경고하다"는 의미.

---

### [6장] 화면 설계

**Q103.** CLI(Command Line Interface)
> 텍스트 명령어 입력 방식. UNIX 터미널, Windows CMD 등.

**Q104.** NUI(Natural User Interface)
> 음성, 제스처, 터치 등 자연스러운 행동으로 조작. Siri, Kinect 등.
> (GUI: 그래픽 아이콘으로 조작)

**Q105.** 유연성
> UI 4원칙: **직관성**(누구나 쉽게) / **유효성**(목적 달성) / **학습성**(쉽게 배움) / **유연성**(요구 수용, 실수 최소화)

**Q106.** 이식성(Portability)
> ISO/IEC 9126 품질 특성 6가지 중 하나. 다른 환경에서도 적용 가능한 정도.

**Q107.** 유지보수성(Maintainability)
> ISO/IEC 9126 품질 특성. 변화 대응 및 확장 가능 정도. 하위: 분석성·변경성·안정성·시험성.

---

### [7장] 애플리케이션 테스트 관리

**Q108.** 살충제 패러독스(Pesticide Paradox)
> 동일 테스트 반복 → 더 이상 새 결함 발견 안 됨. 해결: 주기적으로 테스트 케이스 업데이트.

**Q109.** 오류-부재의 궤변(Absence of Errors Fallacy)
> 결함 0개 = 고품질이 아님. 사용자 요구사항을 만족해야 진짜 품질.

**Q110.** 기초 경로 검사(Base Path Testing)
> 대표적 화이트박스 테스트. 순환 복잡도(V(G))로 테스트 케이스 수 결정.

**Q111.** 결정 검증 기준(Decision Coverage)
> = 분기 검증 기준(Branch Coverage). 모든 조건문의 True/False를 한 번 이상 테스트.

**Q112.** 경계값 분석(Boundary Value Analysis)
> 경계값(최솟값, 최댓값, 경계±1)에서 오류가 많이 발생. 블랙박스 테스트.

**Q113.** 스텁(Stub)
> **하향식** 통합 테스트에서 사용. 하위 모듈 역할을 임시로 수행하는 더미 모듈.
> (드라이버: 상향식에서 사용, 상위 모듈 역할)

**Q114.** 드라이버(Driver)
> **상향식** 통합 테스트에서 사용. 상위 모듈 역할을 임시로 수행. 파라미터 전달·결과 도출.

**Q115.** 알파 테스트(Alpha Test)
> 개발자 환경에서 사용자가 개발자 앞에서 테스트. 오류를 함께 기록.
> (베타 테스트: 사용자 환경에서 사용자가 혼자 테스트)

**Q116.** 회귀 테스트(Regression Test)
> 변경 후 이전에 통과한 테스트를 다시 수행. 새 버그 유입 여부 확인.

**Q117.** 샘플링(Sampling) 오라클
> 일부 테스트 케이스에 대해서만 기대 결과 제공. 전수 검사 불가능할 때 사용.

**Q118.** 순환 복잡도(Cyclomatic Complexity)
> V(G) = E - N + 2 (E: 간선 수, N: 노드 수). 값이 높을수록 복잡하고 테스트 어려움.

**Q119.** 의존성 배제
> 클린 코드 원칙. 다른 모듈에 영향 최소화. 변경 시 파급효과 없도록 작성.

**Q120.** pmd (또는 checkstyle, SonarQube)
> 정적 분석 도구. 코드 실행 없이 분석. 코딩 표준·스타일·결함 확인.

---

### [8장] SQL 응용

**Q121.** RESTRICT
> DROP 시 다른 개체가 참조 중이면 **제거 취소**. (CASCADE: 참조하는 개체도 함께 삭제)

**Q122.** GRANT
> DCL. 권한 부여. `GRANT 권한 ON 테이블 TO 사용자;`

**Q123.** ROLLBACK
> DCL. 미커밋 변경 취소 → 이전 상태 복귀. COMMIT하면 롤백 불가.

**Q124.** WITH GRANT OPTION
> GRANT 명령의 옵션. 부여받은 권한을 다른 사용자에게 재부여 가능.

**Q125.** INTERSECT
> 교집합. 두 SELECT 결과 중 **공통된 행**만 출력.

**Q126.** UNION
> 합집합. 두 SELECT 결과를 합쳐 출력, 중복 제거. (UNION ALL: 중복 포함)

**Q127.** 트리거(Trigger)
> INSERT/UPDATE/DELETE 이벤트 발생 시 자동 실행. BEFORE/AFTER 지정 가능.

---

### [9장] 소프트웨어 개발 보안 구축

**Q128.** 기밀성(Confidentiality)
> CIA 3요소 중 하나. 인가된 사용자만 접근. 암호화로 보장.

**Q129.** 가용성(Availability)
> CIA 3요소 중 하나. 언제든 사용 가능. DoS 공격이 가용성을 침해.
> (무결성 Integrity: 정보가 인가 없이 변경되지 않음)

**Q130.** SQL 삽입(SQL Injection)
> 입력값에 SQL 코드 삽입 → DB 조작. 입력값 검증·파라미터화 쿼리로 방어.

**Q131.** DES(Data Encryption Standard)
> 대칭키(개인키). 블록 64비트, 키 56비트, 16라운드. 현재는 보안 취약하여 AES로 대체.

**Q132.** RSA
> 비대칭키(공개키). 소인수분해 어려움 이용. 디지털 서명, 키 교환에 사용.

**Q133.** 해시(Hash)
> 임의 길이 입력 → 고정 길이 출력. 단방향(복호화 불가). SHA-256, MD5 등.

**Q134.** AAA(=3A)
> 인증(Authentication) / 인가(Authorization) / 과금(Accounting). RADIUS 프로토콜이 대표적.

**Q135.** SSH(Secure SHell)
> 원격 접속 보안 프로토콜. **22번 포트**. 텔넷(23번)의 보안 강화 버전.

**Q136.** SYN Flooding
> 3-way-handshake 중 SYN만 보내고 ACK 안 보냄 → 서버 연결 대기 큐 가득 참 → 서비스 불가. DoS 공격.

**Q137.** 랜섬웨어(Ransomware)
> 파일 암호화 후 복호화 대가로 금전 요구. Ransom(몸값) + Software.

**Q138.** 백도어(Back Door)
> 정상 인증 우회하는 비밀 통로. 개발자가 설치하거나 공격자가 심음. 트랩도어라고도 함.

**Q139.** 제로 데이 공격(Zero Day Attack)
> 보안 취약점 발견 직후, 패치 배포 전에 이루어지는 공격. 방어가 매우 어려움.

**Q140.** 스니핑(Sniffing)
> 네트워크 패킷 도청. **수동적 공격**(데이터 변조 없이 엿보기만 함). 스니퍼 툴 사용.

### [보기 배치 01] 정규화 단계

| 번호 | 정답 | 핵심 키워드 |
|------|------|------------|
| ① | 1NF | 원자값(Atomic Value) |
| ② | 2NF | 완전 함수적 종속(부분 종속 제거) |

| ⑥ | 5NF | 조인 종속(JD) 제거 |

> 정규화 순서: 1NF → 2NF → 3NF → BCNF → 4NF → 5NF (높을수록 강한 정규화)

| 번호 | 정답 | 핵심 키워드 |
|------|------|------------|
| ① | 기능적 응집도 | 단일 기능만 수행 (가장 강함) |

| ⑤ | 시간적 응집도 | 특정 시간에 함께 수행 |
| ⑥ | 논리적 응집도 | 유사 성격 기능들의 묶음 |
